# 外部 Source 的身份与旧授权确认

库ID标识资源，SHA-256标识采用的内容版本，Windows卷号＋文件索引标识一次打开的文件对象。三者分别对账：两个文件可以字节相同，原路径也可以被换成另一个对象。文件名、修改时间和内容相同都不能代替真实文件身份。

## 当前读取规则

外部文件的字节、身份与前后元数据来自同一打开句柄。Windows短时仅共享读取，已有或新申请的普通写入／删除句柄会冲突并返回`SourceBusy`；非普通文件、短读或元数据变化明确失败。这不是对已有可写映射或任意跨OS并发修改的完整快照保证。

持久外部文件授权始终只读取普通文件，路径变成一个合法内容快照目录也不能绕过身份校验。显式临时目录授权仍可浏览快照；插入文档按URI的持久性检查，临时`external://`不会因为内容被归类为snapshot就变成可恢复Source。显式采用`session://`快照可以形成持久引用。

已采用的库版本优先读取实例`library/versions/`中的持久字节，原外链是否待确认不改变这些留存版本。当前库浏览则仍核对原文件，不能靠旧字节掩盖外链状态。

## 旧记录与显式确认

旧`cutrans-external-sources/1`记录可能来自错误的Win32结构布局，其数值不作为修正后的真实身份。加载时保留原始字段与观察hash，标为待确认，不自动探测或改写原catalog。未确认读取返回`legacy_identity_unverified`（ABI状态16），调用方输出长度为0，缓冲区不被写入。

新catalog使用`cutrans-external-sources/2`，每项明确`identity_scheme`：已核验为`win32-file-id/1`，未确认旧项为`legacy-cutrans-layout/1`。混合保存不会把其它旧项改成已确认；新格式写入后不承诺旧程序可以降级重写。

Runtime command API及Host `command_result`提供以下诊断命令：

```text
source.list
source.reauthorize <grant-id> <64字符预期SHA-256> <原绝对路径，余下文本允许空格>
```

`source.list`输出授权ID、身份scheme、是否待确认和上次观察hash，不输出物理路径。上次观察hash可能来自一次未被作品采用的读取，不能自动拿来作为授权凭据。确认所用预期内容版本应来自用户明确选择或作品的Source声明。

确认只接受原canonical路径与本次预期hash相符的实际字节。成功保留授权ID和路径，记录正确文件身份；只原子提交授权catalog，失败保留旧记录。已经确认的同一对象可重复核对且不写catalog，不允许用此命令把授权改给原子替换后的新文件。确认不修改库head、文档、History、Job或Station，也不承担重新定位或采用新版内容的语义。

本阶段提供底层命令及明确错误，完整文件选择／确认向导、资源CAS请求、重新定位和采用新版继续在后续资源工作流中实现。普通GUI帧队列仍有参数容量边界，不以这条底层命令代称长路径交互已完成验收。
