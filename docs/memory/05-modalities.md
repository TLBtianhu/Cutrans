## 四、模态与制式

- **模态全插件化**:核心非常薄=宪法文本(纯数据形状)+注册表容器+索引器;核心对"什么是 video"零认知(编译器强制:modal/ 依赖核心,反向零依赖)。行为件也降为插件是目标方向;地板永远在:共享词汇=纯声明数据形状。
- **模态是刻度不是分类**:特异性偏序——帧可取的流(最高)→视频流/音频流→具体制式→AV(乘积,最低,天然带投影)。宿主性=接口挂在格上的高度;协议检查=格上比较;分表=在轴上选切点,无绝对正确分法。
- **制式={帧率,分辨率}**(族坐标);流只在一种制式下有意义;缓存键必掺制式(树哈希⊕制式)。**流协议 = 模态 × 制式**。
- **模态降级=组织概念,制式=身份证(2026-10-10,用户立法)**:模态在规则层退场,只剩三个意义:①同模态制式族的模板(格式族);②器的创造思路与制式模板(像素思维/采样思维);③分类文件夹(组织)。**制式(共享帧率+模态私有帧内容量)才是流格式的身份证**:装配校验按制式、器的身份带制式、帧 tag 按制式、缓存键掺制式——模态不参与任何运行时规则。模态的残留=帧内容的解释学(这一帧是像素还是采样),归模板层不归规则层。连带:OpaqueBlock 的 tag=制式标签(非模态标签);ModalityBook 降格=格式族的文件夹注册表;聚合器唯一=按制式唯一(over@1080p30 与 mix@2048 窗是各制式各一的聚合器)。**制式二分(2026-10-10 用户定式)**:**帧率=永远共享**(唯一时间轴,AV 帧号统一的根);**帧内容量=模态私有的同级参数**(视频=分辨率,音频=窗长,参数流=速率)——分辨率与帧采样数是同级东西,帧率永远共享。引擎上限档=120fps+1920×1080+2048 窗;剪辑默认档=30fps+1920×1080+2048 窗。**AV 模态后置(2026-10-10,用户修正)**:当前 video/audio 是纯模态(纯画面/纯音频);AV 将来单独定义流协议与制式,制式={帧率(共享),视帧分辨率,音帧窗长}——**AV 与 video/audio 平行同权,不是乘积/特殊形态**(修掉"乘积最底层"旧说:模态注册表里没有等级)。**跨模态/跨制式转换=专门的转换效果器**(同模态不同分辨率缩放/无声视频→AV 加轨等);**效果器天然支持异模态异制式的输入输出**(器的签名不绑同模态,输出 comp 的模态由器决定)。统一引擎红利:纯模态可单播(无声视频/纯音频),AV 流原生支持——**同步不靠程序模拟(传统 OS=同时播放两条轨来"模拟"同步),引擎自带**(AV 帧号索引算术);软件开发因此更轻松。**三播放模态平行(2026-10-10,用户)**:纯视频/纯音频/AV=三种平行模态,各遵各的格式与政策;格式巧妙处=**AV 帧={视频帧, 音频帧} 同帧号结构复合**(对齐采样率律:同一个 t 就是同一段时间)——**转换零成本**:AV→纯=字段投影(免费,只读个字段),纯→AV=配对(配静音或源流帧);欠账政策各自:视频=跳帧/黑屏,音频=静音+渐变保底,AV=音频优先(音永不断,视跳帧)。
- **AV 转换成本勘误(2026-10-10)**:pair 转换≠复制——**传壳不传体**:AV 帧=两个壳(48B),像素/采样本体住源流 L1,配对=O(1) 壳拼装,非 O(n) 拷贝;**AV 流不缓存**(缓存价值公式:pair 成本≈0,廉算贵存),永远现场 pair——"两倍内存"只在强行缓存 AV 流时才发生,而缓存价值公式已禁。AE/剪映的音画同步=伪造(链接移动=偷偷同时移动两条轨);我们=结构真同步(一个 comp 一条时间轴,整体移动/分割=天然原子操作)。
- **AV 流无 L1/L2;器的制式特化(2026-10-10)**:AV 流=纯点播零存储(pair 免算不缓存):has(t)=双上游并查,get(t)=现场拼壳;输入硬前提=**同 fps**(异制式先过转换效果器再 pair),帧数不必一致——各自欠账兜底(音尽=静音,视尽=黑屏)。**器的制式特化律**:帧率对帧器无关(**流的赤裸性:帧不认识 fps**,24 帧器和 30 帧器分插件只在时域流器上成立——窗口长度依赖 fps 的器才分);要特化的是**帧内容量**(分辨率/窗长:SIMD 车道/布局/缓存分块全受益)。默认开发档=30fps+1920×1080+2048 全模态;拓展=模板+分别编译(Zig comptime 泛型档;WGSL 用 pipeline overridable constants;.cop 预编译特化档注意 CRT 同族律),运行时参数档兜底。
- **器参上下文律与转换成本分层(2026-10-10)**:输入流的制式经**装配上下文(ctx)**给器,**不进参数表**(唯一真源:制式跟着源流走;参数表放它=双写漂移——参数说 30 流是 60 的事故);时域器的"秒参数"(残影 0.5s)在装配时经 ctx 换算成帧偏移。AV 合成器输入=两流+两制式(ctx 给),同 fps 前提校验归装配器门卫(不符=拒载红标;插转换器=显式政策,不自动)。**转换成本分层**:壳拼装=O(1) 免费(AV pair);重制式化=O(n) 真贵(缩放/重采样/补帧=像素级重算);**声明永远小(树节点几十字节),物化才贵**——缓存价值公式自动生效:转换器输出值得缓存(L2 收),pair 不配缓存。
- **制式两向律与器的二分(2026-10-10,用户立法)**:**制式分两向**——输入制式=装配上下文(跟随源流,唯一真源,永不入参数表),输出制式=器的配置参数(声明"我要产出什么");启发器=只有输出侧(无输入),变换器=输入 ctx+输出参数——**启发/变换的判据仍是输入数,声明输出制式不改生的种类**(4k→2k 缩放器有一条主流输入=变换,不是启发),矛盾消解。**器的二分**:逐点器(gain/调色类,元素级不认形状)制式无关,泛型一遍写完;邻域器(模糊/缩放/卷积)与时域器(残影/光流,窗口吃 fps)**按制式模板特化**——不同制式的空间处理逻辑本就不同,参数化=无意义旗帜函数(if-else 大旗函数是最差形态);每种制式配专件,模板产出不费开发时。**转换难度不均**:整数倍缩放(1080→540)有快道,分数倍重采样慢道,帧率转换(补帧/丢帧)另一道——转换器按转换对专件化,世上没有万能转换器。
- **制式住声明层运行时消失;器无物种墙(2026-10-10,用户立法,部分取代"制式两向律")**:全特化后,制式=**器身份的一部分**(编译期烧进专件),运行时零读取;输入制式=器的内建期望(装配门卫校验:源流制式≠器期望=拒载红标),输出制式=器的内建声明;**制式的真源=产方器的输出声明**,装配期消费(选核+校验),UI 提示从 comp 声明拿,运行时消失;ctx 传制式作废(藏进上下文=不能信用户记好的半吊子策略)。**器无物种墙**:启发/变换/聚合只是输入数(0/1/N)的刻度,不是制度上的物种——器=统一形态{输出制式声明+N 个输入制式期望+参数 schema};启发器=输入数为 0 的器;Birth 分类仍是树的语义(一 comp 一生),器层只有元数;每个器都是格式制式严格特化的,更顶级先验无必要。**流自身不另带制式声明**(2026-10-10):流的制式与产它的器的声明**绑死**,双写=漂移,故流对象保持赤裸(零制式字段)——要知道流的制式=查产方声明(声明层),不看流本身;赤裸性律与全特化互相成全:流的裸由器的特化兜底。
- **插件两族(2026-10-10,用户)**:函数插件(器 .cop:被动被调,进树,.cut 声明其引用)与**泵插件**(自带活循环,主动,**不进树**——UI/播放器/预产/回放器/音频输出,住装配层与启动配置);"器无物种墙"法只管函数插件内部(启发/变换/聚合=输入元数刻度),泵件是另一族,树永不知其存在。
- **.cop 跨平台路线(2026-10-10)**:Java 答案=统一字节码(.class)+各平台原生 JVM(**jvm.dll——底层确实是 DLL**)+解释器+JIT(HotSpot=热点探测+运行时编译为本机码);我们的路线两选:①**WASM**(zig 直出 wasm32;运行时 wasmtime/wamr 装载;红利=沙箱(失败分层的天然红标区)+真跨平台;行业今天的便携插件答案:Envoy 过滤器/Figma 插件/Zed);②zon 源码包安装期编译(编译期班车,零运行时税)。共同前提=ABI v2(C 形参数签名);择路后置(器 ABI 动工时定)。**JVM vs DLL 速度差(2026-10-10)**:DLL=**已是原生机器码**,装载=mmap+重定位+DllMain,零翻译即全速——Windows 不"翻译"DLL;.class=字节码,JVM 的解释与 JIT 预热成本依实现和负载,不采用固定“慢 10-50×”经验数字;峰值可能接近或超过静态 AOT,故有 warmup 曲线(对策=CDS 类数据共享/GraalVM AOT)。**我们 .cop=原生 DLL 路线=零预热全速**(媒体带宽活预热不起);WASM 路线=基线 JIT 快启动+优化档,介于两者之间。**可移植层的位置(2026-10-10)**:Java=格式跨平台(.class 字节码)+引擎不跨平台(JVM 每平台原生);我们=产物不跨平台(.cop 原生每平台编译)+源码跨平台(zon 包);JIT 稳态后运行时内存里都是本机码(效果同 DLL),差别只在到达路径(DLL 出生即母语,JVM 先口译后写母语笔记有预热)。**硬盘产物的不通用=三层绑死**:指令集(x86/ARM)+可执行容器格式(PE/ELF/Mach-O)+ABI/系统调用接口——源码全平台通用,编一次绑一次。
- **便携 .cop 定案(2026-10-10)**:目标=.cop 像 .class 一样任何系统能加载。设计=**安装包模式(2026-10-10 用户修正,取代双形态缓存版)**:wasm=**安装包形态**(zig 编 wasm32-freestanding,自定义段带声明;下载时住内存/临时区,**安装=门卫四道门+编译成当前平台 .cop 落盘 plugins/,装完即释放 wasm,本地永不留 wasm**);分发仍全平台单文件(仓库只存 wasm,作者免 CI 矩阵——采纳性红利不变);**运行时零 wasm 引擎依赖**(体积税全省),插件表/扫描器/门卫零改动(永远只见 .cop);本地 wasm 不留存无妨(仓库是真源,重装=重下重编);失去 wasm 沙箱常驻档→政策替代:**未信任件门卫拒载**(不装即不险);沙箱档若将来想要=安装期政策分支(需引擎在场,后置)。性能分层:装载即原生全速(安装时已付编译税,低频动作);约束:wasm SIMD 定宽 128 位车道;GPU 类器经宿主函数(WGSL 核住宿主侧,器的 wasm 只管编排)。先例=Android ART(dex 安装期/运行时 AOT)+APK 装完即弃;备选=macOS Universal 式 fat binary(一份多平台切片,加载器按平台选——体积×N,原生零税)。
- **为何不纯 JIT(2026-10-10)**:JIT 的税不是"装载慢一些",是**每次启动都重演 warmup**(基线编译+画像重建,每次启动后头几秒都是亚速)——媒体 deadline 播放最怕的恰好就是头几秒抖;AOT 缓存=编译一次性、装载零翻译、**确定性全速**。我们没弃 JIT:wasm 首载档就是基线 JIT(过渡档),AOT=稳态——JIT 的快启动与 AOT 的稳态全速两头都占。诚实账:JIT 独有优势=PGO 画像制导可超 AOT;但我们的器是带宽活窄分支循环,PGO 红利小。**沙箱与原生化的取舍归政策**:未信任插件=永远住 wasm 沙箱档;签名/仓库审核过的才原生(原生=失去沙箱)。内存税:JIT 在内存里双份(字节码+生成码+运行时),AOT=就一份映射页。
- **AOT 正名(2026-10-10)**:AOT 不是一种格式,是**编译时机**(运行前编译);JIT=运行中编译。**AOT 的产物就是原生码**——我们的 AOT 产物=普通 .cop(DLL/so),与作者直发原生 .cop 同物同格式;双形态因此收敛:**wasm=分发形态,.cop=驻留形态**,全系统原生插件格式只有一种;作者编译期 AOT(传统 .cop 路线)与安装/首载期 AOT(便携路线)殊途同归,产物同物。**N×M→N+M(2026-10-10,用户结晶)**:每插件每平台编译(N×M 矩阵)→每插件编一次 wasm(N)+每平台一台 wasm→原生编译器(M)——矩阵负担从作者群塌缩到工具链;wasm=平台无关的模板形态,AOT=实例化(**分发期的模板特化**,与编译期 comptime 制式特化同构:同一个模式,两个舞台);M 侧由工具链统一维护一次,N 侧作者零平台知识。
- **后缀定案(2026-10-10 修正,取代双形态缓存版)**:分发形态=**`.wasm`**(安装包:wasm32-freestanding 模块+`cutrans_op`/`cutrans_deps` 自定义段——wasm 规范的合法扩展点,标准工具跳过它,门卫 analyze 不执行即可读;从众红利:wasm-objdump 等通用工具直读);驻留形态=**`.cop`**(原生 PE/so/dylib 改后缀,PE 内声明照旧);**无缓存形态**(wasm 不落盘故无双身份问题——缓存版作废)。安装业务流程:**下载 wasm(内存/临时区)→门卫四道门→编译成当前平台 .cop 落盘 plugins/→释放 wasm**;安装=校验+编译+落盘,编译是安装的固有步骤(安装本来低频,编译秒级)。
- **引擎也走 wasm→cop(2026-10-10,用户)**:escapement 引擎本身=插件(泵件族),分发同法:wasm 进→安装编译→原生 .cop 落盘;成立的理由=**引擎是胶水不是内环**(每帧 120Hz 的跨 DLL 调用成本可忽略,内环热活在器和口岸后端里);comptime 泛型不是阻碍——ABI 边界本来就类型擦除(ABI v2),泛型特化住在器与后端的内部构建里。**拆分**:引擎核(可移植逻辑:骨架循环/门禁/欠账政策/主钟)=wasm→cop;**口岸后端(要直接调 Win32/CoreAudio 平台 API)=原生 per-platform .cop**(wasm 沙箱碰不了平台 API;后端是我们自己写的,M 侧本来就归我们维护);引擎.cop 的依赖声明走 cutrans_deps(依赖 modal 包);宿主性≡入度——引擎是高入度插件(**进不进自动加载集归政策层**:自动加载器/拓扑排序器等高级加载管理器本身也是插件;**最薄状态=万物现场加载**(2026-10-10 用户正名)——自动加载集不是底层概念,是政策层的配置文件;底层只有源四动词(scan/analyze/carry/remove)+门卫校验件,exe 薄到只会现场 carry)。**引擎=驱动式更新件(2026-10-10,用户)**:输出栈是腐烂最快的层(平台 API 变/新设备/驱动怪癖),引擎与口岸后端=独立更新通道的插件——英伟达驱动同例(独立通道高频更新,与宿主版本解耦);更新频率分层:核=宪法级稳定,引擎=中速,口岸后端=最快(驱动式);更新政策=默认跟踪最新修复,项目钉版本归 lockfile(表=最小版本钉住单位,老法)。
DAG 三读数:宿主性=入度(定加载顺序)/真源性=离源距离(定存储必要性)/解耦性=接口宽度(独立第三轴)。
- **默认工作制式(2026-10-10 定稿 v2)**:剪辑空间默认=视频 **1920×1080(横屏)@30fps**+音频 **2048 采样窗@30fps**(=61440Hz);用户可自选 24/60/120(制式=族坐标,缓存键掺制式照旧);**引擎上限=120fps**(对齐现代 120Hz 显示屏;上限档音频=2048 采样窗@120fps=245760Hz)——**引擎只管把上限尽可能扩大,工作制式归用户选**。**音频窗长恒定 2048**(默认与上限档同窗),采样率=2048×fps 纯导出常数。内部精度 float32。**分析/编辑与协议帧细度解耦**:音高编辑/大范围音频编辑=流变流+按需长窗分析(宽度够),协议帧细度只是存储与播放 API 的形式,两者不矛盾(存储/分析分家的兑现)。
- **对齐律**:每模态采样率=2^n×fps 且 ≥44100——AV 帧号空间统一(音 n=视 n),同步业务=索引运算;内部制式不受外部生态习惯污染,出口采样率归口岸转换(重采样便宜近无损)。
- **模态插件化四层**:①源码包(zig zon,编译期班车,模态定义唯一真源)②核 DLL(装载期)③器 .cop(运行期)④模态包 .cft(分发期 kind=modality:manifest+core.dll?+ops/*.cop+presets/*.cut)。
- **开放帧型车道**:OpaqueBlock{tag,len,data}+OStream——第三方模态 tag 自报进场,机制层零改动。内建模态清单=类型的 comptime 投影(@typeInfo 机械生成防漂移);开放模态清单=真源本身(作者手写)。模态定义(帧型+清单)与处理器(器族插件)分家。
- **器依赖双轨**:模态包+模态无关帧器;很多器不吃模态。
