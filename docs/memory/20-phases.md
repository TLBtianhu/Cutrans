- **语义 ABI 与 C/C++ ABI 分家(2026-11-02 用户校准)**:自定义 VM/新语言不必继承 C++ 对象布局、虚表、RTTI、STL 类型或异常模型。`.cut`、CCB/CUI、Task、History、VM Pack 与语义 DSL 只承诺固定宽度/端序、记录长度/数量/版本、稳定 id/引用/生命周期、浮点/字符串/错误/所有权;实现可由 Zig/C++/Rust 任意生成,语义不随编译器变化。原生边界仍须处理 OS/CPU/调用约定/库装载,故只保留固定宽度标量、不透明句柄或 id、明确 buffer/错误码/释放函数的窄 C ABI Port。结论=C++ 对象 ABI 可在语义层消失,OS/原生 ABI 只能隔离不能忽略;不得借“VM 自定义长度”跳过 native 自检。

- **VM Native Environment(VNE,候选名)虚拟化方向(2026-11-02 用户提问,设计提案非现役完成)**:目标是 VM 内 Pack/应用只见稳定的 VM 原生环境,宿主 OS 从它们的依赖闭包消失;不是 VM Runtime 自身不需要 OS。绝对无 OS 只能转向 bare-metal/hypervisor、驱动与硬件适配,不采纳。分层=语义数据→VM 系统服务 ABI(闭集调用+opaque handle+定长消息)→每平台 Runtime+窄 Port→宿主 OS。虚拟根=`pack/session/cache/runtime/temp/external-grant`,文档与 Pack 不存 `C:\`、`/home` 等宿主路径或裸 URL;外部文档经 Bootstrap 授权成 handle/capability 后进入 VM。虚拟设备=Clock/FrameSink/Audio/Input/Storage/Network/Secret,传 id/帧号/单调 deadline/定长消息,不传 HWND/fd/errno/裸指针;Task 不暴露 OS 线程,错误归一,RuntimeContext 是实例内核状态而非全局单例。能力授权按实例;不可信代码仍走进程隔离或 WASM,VM 同进程不等于安全边界。原生热路径保留,不给每次文件读写/像素处理强塞 RPC;高风险编解码/设备后端再按需拆 Port broker。验收=同一声明/命令/输入日志在 Windows/Linux/macOS 得到同语义指纹与状态,虚拟 Clock/Devices 可回放,并扫描语义包禁止 OS 符号、宿主路径与 native ABI;不承诺跨 OS 像素、字体或设备时序完全一致。优先 VNE 边界而非全系统 WASM 化,WASM 仍是可选插件车道。
