- **事件物理律(2026-10-13 问答立法:树=内存/泵=时钟,那事件触发是什么物理现象)**:拆两半——**"何时发生"=主从锁存器(沿触发器)**:两个电平敏感锁存器反相串联,把一个电平跳变判决成一次捕获——事件的物理原语=沿捕获(门的兄弟:门把电平判决成 0/1,主从对把跳变判决成"发生了");**事件=tick 沿 ∧ 使能**(寄存器写使能=许可,沿来了使能没开就不算数)。**"算哪通哪"=译码器查表**:指令=存储的位型(载荷统一律),操作码查译码 ROM/PLA→几十根控制线(mux 选择/ALU 功能码/各寄存器写使能)→通路打开→电荷沿通路流动(每级门再生判决)→沿+使能捕获进 B。中断=控制状态机的一根输入,在下一指令边界被查到(轮询守恒律),掰向中断向量表。**收尾同构:译码器/中断向量表=硅里的命令注册表(位型/中断号→控制线/入口)——command.zig 的"命令名→处理函数"与它是同一张拓扑;硅用 ROM 查表,我们用哈希查名,都是 decoder**。宪法不是像计算机,宪法就是计算机,从硅一路同构上来。
- **环泵的存在理由=秩序立法,不是可靠性补丁(2026-10-10)**:OS 的并行是**忠实但无序**——它不会弄丢你的活,只是不承诺谁先谁后;数据撕裂的根因是**秩序缺席**,不是执行不可靠(两个线程都被忠实执行了,坏就坏在交错上)。**不可预判成立,不可靠不成立**。更深一层:就算 OS 调度完全可预判,环和泵照样要建——并发事件的"同时性"是世界固有的(用户点击与 AI 发令物理上同时,无先验正确顺序),环的作用=**我们自选一个序**(到达序=总序),泵=按序执行;锁=防撞不定序(互斥),环=定序(全序)——树的命令日志要的就是全序,故选环不选锁。开世界(线程交错)被环收编成闭集总序,事件溯源因此成立。
- **队列=时间重分配器(2026-10-10,用户结晶)**:随机触发→缩减成微小动作(UI 解析=翻译+写入任务清单)→执行被重排成脚本。**队列=活的程序,泵=取指器**(pop-dispatch-execute = fetch-decode-execute;程序边跑边被写——自我修改代码,冯·诺依曼机的队列版);脚本化=协调浪费归零(无锁/无抢占/无撕裂,时机全优);但**最优性有条件**:消费≥生产(Little 定律,失衡则满+政策兜底);环不止串行还**可重排**(优先级三轨:触发无序,执行按我们的政策有序——比"到达序"再进一步);泵上纪律被用户独立推出:解析时间<执行时间则必有"第二个触发来了来不及应付"的风险→handler 只许翻译+入环,重活甩工作池;泵不轮询清单(睡到队列非空,零 CPU),"转得慢"=睡眠不是空转。
- **泵的提升抽象(2026-10-10)**:前端泵抽象两族=**Observable 流操作子**(RxJS:map/filter/debounce/throttle/merge/takeUntil——事件流当一等值组合)+**Signal 自动依赖跟踪**(Solid/Angular:读取即登记,变化自动传播)。我们的映射:①**命令流操作子=环的政策件**(防抖/节流/合并/超时=命令环上的流政策插件——RxJS 学来当政策层,机制不进核);②依赖跟踪=**树哈希级联已有**(变化检测全自动,改参数→哈希变→失效锥自动划),UI 层的 Signal 同构件后置;③Promise=我们的**票根回执**(⑤),但比 Promise 强:可追踪可取消可审计(回执带号;observable 是发完即忘);④**账本谓词可等待**(await has(t))=播放器插件原语——门禁律的句柄形态。
- **泵在非随机链上的作用(2026-10-10)**:随机性吸收只是泵的第一作用;完全可预判的链上,泵/队列还买六样:**节流**(各阶段速率不匹配的缓冲)、**优先级重排**、**并行展开**(多工人)、**可观察可记录**(账本/进度条)、**可取消**(帧边界)、**故障隔离**(阶段之间)。输入泵(UI/AI)是唯一真随机源,其余泵是链式带动——链式≠无价值。
- **命令环的满与过期(2026-10-10)**:默认入环=时间序(FIFO=到达序,环的物理);重排归取件侧政策(我们=多环分级+排干序,不做环内重排);环里躺的是**意图(声明)不是调用(执行)**——声明/执行分家。**满=背压不丢弃**(命令=用户意图,不可再生——排队寿命三保;可再生才配丢,帧令可丢命令令不许丢);"没满也拒收"=准入控制(模态忙态)归 UI 政策层。**Windows 连击教训**:队列保序但丢时效与语境——卡顿期点击全录,卡完逐一执行 5 分钟前的发泄点击;病根=①意图无时间戳无过期语义②坐标寻址(布局变了打错人)③队列不可见不可取消。处方=意图带时间戳+过期分级(保存永不过期/瞬时值快过期)+同类合并(coalescing,WM_MOUSEMOVE 先例)+**身份寻址**(点是"按钮 X"不是"(350,220)",查无即弃=惰性取消律)+队列可见+可清空(用户看得见、能撤回)。同情面:不丢输入的默认是对的("保存"不能丢),罪不在录,在无时效无语义无可见性。**按时间量级分并发域**:渲染导出等长活独立线程/工作池,UI 泵只翻译——用户独立推出。
- **插队可以,打断不行(2026-10-10,用户立法)**:**任务级取消打断不存在**——插队只重排"未开工"的队列项,在途函数调用永远跑到完(半帧作废=纯浪费);并行靠 CPU 线程调度承担——**OS 抢占线程免费(寄存器存档,恢复无痕),取消任务昂贵(半成品是垃圾)**,所以抢占归 OS,我们只管排队。**分域判据=(重要性 × 时间量级)**:UI 投影(轻+急)最高优先环;编辑令(轻+急)树泵;**失效标记(廉价即时)与重产(昂贵排队)拆开**(树变→立即标失效,慢慢重渲);渲染导出独立工作池;音频硬实时 IRQ。Windows 卡死连击病的根治:慢动作与快反馈永不排同一条队,并行归 CPU 调度,粒度细到约等于独立同步。例外:取消存在但只在**帧边界**(合作式标志位,导出取消同此),永不在函数体内打断。行业对照:AE 得一半(导出独立队列)失一半(细粒度没分),Windows 全失。
- **并发度两轴分家(2026-10-10,饮水机定律)**:逻辑分拣无限细(环按职责/优先级类随便分,**连续谱**,无二元前后台——Windows 前台/后台二分是粗糙先验);**物理并行度=资源通道数**(核数/磁盘/网卡——出水口多于上层流量=全员变慢,泵按核数开);**任务可暂停性决定抢占合法性**:打水可暂停(无中间态,抢占零浪费)vs 渲染半帧作废(中断纯亏)——故抢占只归 OS 线程层,任务层只排队不打断;紧急=优先级(时间权重),不是更多车道。**用户态引擎法**:无权改 OS 就自建用户态调度器(Go GMP 运行时/游戏引擎 job system/数据库 buffer pool 先例)——泵框架=我们的用户态引擎(环分拣+工人池+亲和性+大页),引擎级优化不碰 OS。
- **权重线程律(2026-10-10,用户结晶)**:**环优先级管未开工的,线程优先级管已开工的**——两级调度合流:急件令进高优先环(环重排),急件线程持高 OS 权重(线程抢占);闲件被抢占时**零作废**——上下文切换=全状态存档(寄存器+栈指针,内存原样),恢复后从半帧接着渲。**抢占≠作废:作废只发生在逻辑层主动取消,OS 抢占是暂停+存档**。完形:插队(环重排未开工)+抢占(线程权重已开工)=完整调度,"打断作废"从系统里消失。红利:无锁环→**优先级翻转免疫**(无锁可翻转——高优先线程永远等不到低优先线程手里的锁的场景不存在)。边界:权重分配的是 CPU 时间,**内存带宽仍共享**(带宽密集型任务互相干扰不归权重管);极端优先级会饿死系统,闲件只用"低于普通",不用实时级压满;通道数仍按核数(权重定"谁先吃",核数定"能同时吃几份")。
- **等权并行默认,权重只跨量级(2026-10-10,用户自我修正)**:线程间尽量等权(同域工人池同权:吞吐最大、无翻转无饿死);权重只用于时间量级悬殊的**域间粗隔离**(音频实时>前台>闲时,少数几档);细粒度优先级=环的排干序(泵内政,动态可调零成本)。**并行的正当性两条**:①核是物理存在,不用=浪费;②吸收不可预判的到达与时长(开世界)——打水单口排队最优的前提是脚本式闭世界(100% 可预判顺序),触发开世界没有这个先验,才要并行+缓冲。通法:**动态序归环,静态档归线程权重**。
- **线程权重退场(2026-10-10,用户再修正)**:任务粒度细(帧级)+限时切片⇒**在途等待上限=一帧**,队列排干序已够,线程权重基本退场;急件本身快(UI 投影 µs~100µs 级),而人眼感知阈≈16ms(60Hz)——权重加速的收益低于感知阈,成本(翻转/饿死/复杂度)是真的;修"几纳秒"的说法:抢占的真实收益=在途任务剩余时间,不是纳秒,只是帧粒度下这个剩余≈1 帧,本来就不长——**粒度细了,权重没战场**。例外:音频 IRQ 回调=驱动自有实时线程(Windows=MMCSS "Pro Audio" 注册,不归我们管);哪天出了不可切的粗任务,权重回抽屉。Windows 对应做法:前台提升(Win32PrioritySeparation——前台进程线程优先级提升+时间片加倍,性能设置里"程序 vs 后台服务"开关即此)+后台压制(EcoQoS/电源节流/UWP 挂起/工作集修剪)——权重粗粒度域级、细排序归队列,行业同法。
- **全员等权终版(2026-10-10,用户终版)**:**我们自建的所有线程等权,零权重声明**;优先级全归环的排干序。音频实时性≠权重问题,是**硬时钟回调纪律**:声卡=硬件钟+DAC+DMA 缓冲,驱动的钟每周期(如 10ms)回调你一次"填缓冲"——回调里只许轻活(提前备好的帧拷贝进去即返回),防爆音靠①回调轻量②缓冲深度(深=容错大延迟大,权衡)③不靠权重;唯一加权线程=音频 API 自己的回调线程(WASAPI/MMCSS Pro Audio),是 API 内政不归我们声明。视频预览同构:显示 API 的 vsync 泵,丢帧可忍(欠账形态律),也等权。**欠账形态律才是真正的音频优先机制——纪律,不是权重。**

- **前端跨平台且快的答案(2026-10-10)**:浏览器=各平台原生的**巨型引擎**(V8:Ignition 解释器+Sparkplug 基线 JIT+TurboFan 优化 JIT,隐藏类/内联缓存/推测优化——几十年 JIT 研发的怪物),JS 文本是便携层;"快"的第二半真相=重活(排版/绘制/合成/解码/WebGL)全在引擎原生层,JS 只指挥。代价=引擎常驻巨大(Chrome 内存笑话)+每次加载付 warmup/GC 税。**对照我们:复杂度放编译期**(zig 编译器每平台一份,但装完即下班,用户机器零引擎常驻),**前端复杂度放运行时**(引擎永远上班)。前端模型的真正优势=引擎预装故内容极小极快(URL 即开)——这是分发红利,不是性能红利。
- **心智模型补(2026-10-09)**:脚本=集权占有时间轴(叙述者:"下一步是什么我规定");泵=交出时间轴主权,只登记"来了怎么办"(接线员)。真实程序=**泵壳脚本馅**(handler 内部仍是顺序小脚本),无纯泵也无纯脚本(main 外永远包着 OS 大泵)。**同步调用=异步通知的特例**:调用者压栈后睡到被调者返回——栈与队列是同一"睡等"的两种睡姿(LIFO 嵌套/FIFO 排队),popBlocking 与函数调用的等待在物理上是同一动作(线程挂起)。**泵语言 GC 的根源=开世界寿命不可预判;我们的免疫机制=消息只带身份(值语义)本体住表**——事件寿命问题在架构里掐死;泵框架设计红线:队列里只许走值大小的身份。**调试心智**:脚本 bug=错逻辑(可复现),泵 bug=时序(不可复现,heisenbug);驯化术=**录制事件流回放成脚本**(Redux DevTools 时间旅行/rr 记录重放先例)——我们的"UI 解释器纯函数+命令可录制回放"即此;AI 调试通道=.cut+命令日志。
