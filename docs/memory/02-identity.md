## 一、身份宪法

1. **一切皆插件**。不存在绝对的宿主/插件分界,只有依赖关系与加载顺序。**宿主性 ≡ 入度 ≡ 自动加载性**:被依赖越多越像宿主;"软件的感觉"=它默认加载哪些插件。exe 唯一职责=读 config → 按依赖 DAG 拓扑序加载。旁证:dsh/Cordis(DeepSeek harness,"Everything is a Plugin",无特权核心、自声明、高扇入基层)。
2. **声明唯一真源,一切皆投影**。树=唯一真源;预览/伪代码/二进制/AI 视图全是投影。**声明优先,光栅化是出口不是入口**(AE 病根:把声明式内容强行光栅化成伪素材才能进管线)。
3. **纯度:机制与策略分家**。机制无先验(轮子只管怎么做),政策上浮边界(何时做是策略,策略即插件)。逻辑预算法则:内存预算随便花,逻辑预算省着花。
4. **剪辑即编程**。工程=代码库:树=AST,.cut=源码,表=manifest/lockfile,素材=assets,导出=build artifacts。工程文件 KB 级纯声明,可 diff 可进 git;.cut 对人/机器/LLM 三方同构可读。编辑器=可视化编程环境。
5. **形态**:启动器(独立进程)+ 剪辑空间(独立进程:工程文件+内存树);多工作空间=多进程(真隔离)。**启动器的本质=特异文件资源管理器**(2026-10-09 正名):管理对象=插件/下载/装配/工程文件,任务形状与 PCL 相同;动机=避免传统 DAW 的插件配置混乱(FL 扫路径那套)。先例:PCL(MC 生态的插件/版本/下载治理)、剪映亦有启动器概念(但偏科工程文件的保存管理)。
6. **元规则纪律**:立法先问"这条规则对任意类型成立吗"——成立进核;只对某类成立→数据/插件;只对某场景成立→调用方政策。不问"AE 怎么做"。
