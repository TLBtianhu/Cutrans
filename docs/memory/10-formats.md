## 九、压缩与格式法

- **协议永不压缩**:压缩=用 CPU 换空间与带宽;协议内传输是函数调用,换无可换。被计算的数据要裸,被存放/运输的数据要压。压缩三居所:驻留格式/磁盘缓存/导出格式。例外车道=压缩直通(纯搬运不解码,Stream<包> 合法实例化,opt-in)。
- **驻留管存,效果管算,边界转换,链上直通**:效果器区域=进区解成 raw、链内纯 raw 直通、出区才压(不打乒乓);解码是懒的(用到第 N 帧才解第 N 帧,帧内压缩⇒单帧 O(1) 随机解)。
- **三个"快"**:算法快/硬件快/带宽快;搬运与计算是两套资源(ALU/DRAM/SSD 延迟数量级不同,具体比例依设备与访问模式,不使用固定“SSD 十万倍”口径)。raw 只在工作集合法:1080p f32 帧 33MB,DRAM 上 raw 直读≈压缩+重解打平——压缩红利收窄为容量/磁盘 IO/融合流式消费,别吹过头(自我纠错存档)。
- **行业三派**:帧内有损(ProRes/DNxHD:DCT+量化+熵编码)/帧内无损(FFV1/FLAC:预测+残差熵编码)/帧间(H.264:运动补偿,百倍但杀死随机访问)。**"帧压时间不压"=intra-only=驻留资格核心**(牺牲帧间十倍压缩率,买回时间轴绝对随机访问)。
- **驻留资格四门槛**:帧内独立/解码廉价(≈memcpy)/无损或近无损/系统原生解码。**格式与角色解耦**(素材/驻留/导出是角色不是户籍;codec 表条目自报能力,资格由属性考评推导)。
- **编解码器表**:name→{encode,decode};解码启发器/导出器/驻留缓存三方按名引用。格式=规范文档、编解码器=执行者、容器=封装壳,三分。
- **CRLE(自研,C++ 版已验证)**:像素级行程(16B premult 单元),两 token(字面量/连跑),自描述包("CRLE"+version+w+h),逐位无损,decode 指数自拷贝≈memcpy;实测纯色帧 65536B→37B。定位=内部驻留编码(无后缀,键即名)。zstd=字节盲通用(合成内容透明区屠杀,GB/s 级)。H.264=法度化通货(先验装机量∞:既是压缩器又是交换标准,"先验装机量决定格式合法性"的最大案例)。
- **可伸缩编码路线**(用户认定的美:信息按重要性排序、截断即降级):短期梯子(多档各压,零新逻辑),中期小波进 codec 表,远期神经 codec。**神经时代:压缩=提取**(编码器前向)。
- **AI 消费双通道**:结构理解走树(.cut 直接喂 LLM,零物化);内容理解走物化(AI 访问模式=批量顺序→预产轨客户)。档位全景:raw 全分辨率(编辑)/低清档(预览+AI 理解,同树低制式物化零新概念)/潜空间档(AI 生成,键含模型版本)/导出档(分发)——同树多物化,失效各自独立。
- **格式法**:内部格式自由(编解码自洽即合法),对外格式从众(先验装机量)。格式三问:谁读它/活多久/精度约束。**PNG 与 cft 定案(2026-10-10)**:像素画默认 PNG——行业验证的无损压缩,**素材即压缩态**(省空间归格式自带),加载=PNG 解码启发器(素材入境口岸),我们零自造;.cft 束保留独立后缀、不改名 .zip——**jar 不 zip 同律**:束是给运行时的包裹(manifest 在内),不是给人的压缩包;后缀差=身份与双击语义差(双击 zip=解压,双击束=交宿主)。
- **后缀终版(2026-10-10 修订)**:.cop 器(单件)/.cft 束(zip 改后缀,docx/jar 同族;kind:material/modality/preset)/.cut 树的伪代码专属(生产声明——保留理由:伪代码是程序形态,太重要,扫描先验正当)/**素材文本=直接 .txt**(从众:随便哪个编辑器都能开;身份靠素材表登记+文件内 kind 声明,不靠后缀;原自定义 .ctx 废除)/.json 表/**磁盘缓存裸奔无后缀**(键即名,无身份只有键故无衣)。
