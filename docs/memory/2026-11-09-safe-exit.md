# 2026-11-09 环境内安全退出

## 目标与边界

用户要求的独立“退出虚拟环境”入口开始落地：窗口关闭只离开 Shell，显式退出才停止 Host。本轮不把普通 `stop` 直接包装成成功，也不把单文件发行、不可信插件沙箱或强制抢占式取消混入该切片。

## 生命周期

```text
running
  → 草稿保护检查
  → prepare_stop：Host 停止接受新业务
  → 等待已有任务，或 cancel_jobs 请求协作取消
  → active_count=0 且没有待保存终态
  → 提交已成功的 Shell 身份
  → 既有 stop：暂停驱动、冲刷结果、保存文档、持久化 stopped
  → 关闭 NanoUI Shell
```

- `vne/host_protocol.zig` 新增 `prepare_stop`、`cancel_jobs`、`resume_work`，协议版本仍为 1；旧 `status`／`stop` 行为不变。
- `stopping` 时只放行作业读取、既有 Shell 身份提交、输入录制结束和必要的帧状态收尾。新编辑、导出、授权和其它业务 RPC 返回 `invalid_state`。
- `cancel_jobs` 调用同一 Runtime 命令注册表的 `task.cancel_all`，逐个复用原有持久取消语义；已有作业驱动继续工作，直到正常 `stop` 才暂停。
- `resume_work` 在尚未最终停止时恢复 `running`，无需重启 Host。停止保存失败后的 `degraded` 不自动恢复业务，必须重试停止或仅离开 Shell。
- `shell/client.zig` 的 `ExitHooks` 在停止前提交 Shell 身份，`runAttached` 不重复提交；只有 Host 确认 stopped 且 Shell 正常返回才输出 `CUTRANS_SAFE_EXIT_OK`。

## NanoUI

`apps/desktop/exit_model.zig` 提供独立退出页：等待完成、取消未完成、返回环境、保存失败重试和仅关闭窗口。退出中禁用其它业务操作，正常停止前不请求关闭窗口。

`apps/library/work_model.zig` 的 `beforeClose` 复用为草稿保护屏障：未完成输入、组词、在途请求或未保存草稿不能开始退出。保存草稿不等于提交工作 revision，退出不替用户提交正文。

`--exit-demo` 是内部隐藏验证入口，仍调用真实退出按钮与 Host 编排。它在隔离数据根制造一次保存失败，验证修复后重试，不打开可见窗口，不模拟真实键鼠，也不代替视觉／IME 验收。

## 已明确的非目标与风险

- 取消是协作取消；正在执行的编码器和 OS 调用不能被承诺强制抢占。长时间 I/O 的等待边界仍按现有任务模型处理。
- Host 的业务 RPC 停止受理不是 OS 沙箱，也不是对任意本机 ABI 调用方的访问控制。
- 控制传输失败或结果未知不能显示“已安全退出”。需要保留 Host 状态、允许修复后重试，不能用强杀代替正常停止。
- 旧 `stop` 仍是普通 Host 控制命令，不因新增界面而自动获得全部界面编排。
- Payload 仍外置，安装器公开入口尚未切换，最终单文件发行未完成。
