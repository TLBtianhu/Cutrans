## 七、依赖与装配

- **依赖=动作的需求单,不是实例的关系**("A 依赖 B"=执行 A 这个动作需要 B 在场;cop 依赖幻觉的根=程序持续运行=持续动作,需求看似物的静态属性)。广义依赖成立:cop 缺失=装配依赖(硬);素材缺失/工程不全=内容依赖(软,红标降级,AE 离线素材彩条占位先例)。
- **依赖声明终稿**:每个 .cop 导出 cutrans_deps **纯名单无前缀**("video,gain,rle");analyze 期 peek 读取,不执行插件代码即可静态画出依赖 DAG(静态拓扑/缺失早发现/环检测)。声明哑,装配器响;缺失政策=旋钮三档:拒载(硬,默认)/红标降级(软)/等待(dsh inject 式激活依赖);自动补装归政策插件,声明永远哑。
- **装配器=门卫**:唯一职责=合法性检测(依赖齐备放行/缺货拒载+红标),随时在岗(装载是随时的动作,不是启动一次性);批量按序自动装载=门卫之上的政策插件,后置。
- **失败分层**:不可控崩溃区=引导 exe 自己的 DLL 闭包(main 前,OS 装载器直接崩);可捕获红标区=之后一切。**薄核战略=把尽可能多的失败搬进可捕获区**。Windows 126 不说缺的是谁→依赖检查必须自建(我们的依赖对象在 OS 词汇表里不存在);自建层全平台一字不差,OS 方差关进 source/ 四动词。
- **静默不存在**:装载四道门——①名单核对(注册表 has?)②签名安检(ABI 握手)③依赖核对(cutrans_deps 逐项)④放行装载;每道失败都有名字、有红标位、有拒载语义。反例:AE/VST 静默不载=我们删掉的失败模式。
- **缺货显示立法**:原地红标(标在引用它的节点上),**绝不弹窗**(反 AE jumpscare);四级缺货可枚举:模态缺失/流效果器缺/器具缺/素材断链。
- **表的两态**:内存态(已装运行注册表)与硬盘态(可装声明清单)不对应且不该对应;桥=装配器。cop 进内存即失忆(不知硬盘出处)→名↔路径表记出处,没记则反问扫描器(内容反查)。拆分判据=职责不同才拆(机制无先验,职责有先验)。
- **一表=一查法+活法+死法的组合(2026-10-10)**:表的数量不由数据种类定,由三轴组合数定——**查法**(键型:按 id/按名/按帧号直达,或流转不直达)、**活法**(真源持久/易失可重建/流转短命)、**死法**(缺了=红标/断链/重算)。同组合合并(参数节点与视频节点同住 comps——模态平等就是这么来的),异组合分家。"两桶方案"(一桶存帧+一桶存指令)的死因:指令桶里藏着三种活法冲突的物——器(可执行码,易失,缺了红标)/树(声明,持久真源,缺了断链)/令(流转消息,短命,住环不住表)——塞同一桶=共用同一把锁、同一种备份政策、同一条寿命,全错。
- **加载=触发动作(不可预判)**:地址三来源——人手拖入/硬盘表读/索引器扫描;加载器哑(收地址就装),来源管触发。
