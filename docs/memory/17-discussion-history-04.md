- **亮相=投影律+声明独特≠代码独特律(2026-10-14 用户两问撞已有的律后综合)**:①"满载参数的结构帧在 UI 亮相感觉像变长结构体"——感觉正确但变长的是**投影不是帧**:帧槽(schema 定长,合成器常数时间读)纹丝不动,显示路径把帧经显示策略投影成参数面板=定长控件声明行×变长数量(文档槽,数量维可变);"亮相确实变长"与"帧永远定长"不矛盾——**同一份数据两个读者两种形状,各守各的法**,变长感=投影生效的证据。②"每帧槽位独特→每个要独特 UI API→乱"——乱感来自把**声明的独特**误读成**代码的独特**:声明必须独特(N 效果器=N 份注册表行{路径→类型,提示,getter/setter},这正是结构帧金属感的意义);代码绝不独特(通用控件引擎十几种模板,float→滑块/color→取色器/enum→下拉,几千字段按类型分发——RNA 推导链第④步:控件由字段类型决定不由字段身份决定);**N 效果器=N 份声明+0 行新 UI 代码,统一风格不是目标是自动结果**(所有面板过同一套模板+同一份主题数据)。要设计的只有一次的=类型→控件映射表(显示策略)+主题。特例收口:独特交互(曲线编辑器/色轮)=往引擎注册新控件**类型**(Blender CurveMapping 同款),任何标该类型的属性复用——类型维扩展非效果器维定制。**两问合并一句话:帧定长+声明独特(帧槽的法);投影变长只在数量维+代码全通用(文档槽的法)**。

- **DeepSeek Search API 接入记录(2026-10-22)**:DeepSeek 新发布的搜索/抓取是**独立 JSON API**(POST /v1/tools/search + /v1/tools/fetch,Bearer 鉴权)——**既非模型也非 MCP 插件,是托管工具 HTTP API**(无模型字段/按次计费 5元每千次成功请求/失败或无结果不计费;Claude Code·Codex server 端调用 2026-11-01 前免费)。返回字段:rerank_score(0~3,≥1.5 优质)/authority(0~4,≥3 极权威)/date/snippet(100~200字给人看)/**summary(600~800字给模型读)**/content(need_content=true 才带正文);query 支持 site:、-、双引号、lang:、after:、before: 语法;限速 search 100QPS/fetch 25QPS。已包成零依赖 stdio MCP server(C:\Users\<user>/.zcode/mcp/deepseek_search_server.py,工具名 search/fetch,urllib 直连绕过代理),注册在 ZCode **用户级** ~/.zcode/cli/config.json 的 mcp.servers(key 存该 env 字段,**不入库不入 MEMORY**),会话启动时自动连接,新会话起可用 mcp__deepseek-search__search/fetch。**MCP 的定位**:MCP 是 agent↔工具之间的协议,DeepSeek 端点是裸 HTTP;在 DeepSeek 自家 Harness/Claude Code 里它是 server 端内建工具,在我们这里 MCP server 只是适配层——**本质是托管能力 API,MCP 是接进 agent 的桥**。
- **AI 搜索引擎原理结晶(2026-10-22)**:AI 搜索不是替代传统搜索,是在其上**四个加注点**:传统底座仍在——定期爬虫+倒排索引(token→posting list=名址分离律的工业实例)+BM25+链接分析排序+返回蓝链清单(人脑综合);AI 加注①**查询理解**(LLM 改写/分解/多路扩展查询)②**语义召回**(段落嵌向量+ANN 索引,抓同义改写——关键词=字面符号重合,精确但错过改写;向量=嵌入空间邻近,抓语义但会漂移;工程标配=hybrid 两路召回合并)③**神经重排**(cross-encoder 判 query-doc 相关=rerank_score 字段的真身;authority=PageRank 后裔的来源权威先验)④**阅读综合**(LLM 读 top 文档产带引用的答案)。**爬虫维度两家一样要爬,区别在"定期建索引=广而旧"vs"实时抓取=窄而新"**——DeepSeek 把 search/fetch 拆成两个端点正好暴露这个结构。**一源两投影又一实证**:结果条目里 snippet(100~200字,前端展现)与 summary(600~800字,模型阅读)双字段=同一内容面向人读者和模型读者的两份投影,与文档对偶律/一树两读者律同构。

- **索引期向量化必然律+查询侧可替代/索引侧不可替代(2026-10-22 用户洞察拧正)**:语义召回=**双索引双路召回**(建库期文档段落嵌入成向量索引 ANN/HNSW+倒排关键词索引;查询期查询嵌入,两路合并)。**文档嵌入必须在建库期完成是物理必然**——不可能查询时给全网现算嵌入(O(全网) vs O(一次ANN查找)),"建表时就向量化"不是附加项是唯一架构。**查询侧预处理可被强模型自替代**:改写/分解查询强 agent 自己 agentic 循环做得更好(查-看-修正再查,比 API 内建小模型改写更贴上下文);细节活必须读原文(need_content/fetch),小模型摘要丢细节为真;但 summary 的正确定位=**廉价初筛**(十条结果各 600~800 字让强模型低成本决定哪几条值得抓原文),省的是强模型上下文不替代其阅读——**分层:初筛用摘要(有损便宜),深读用原文(无损要钱)**。**索引侧不可替代**(自建不了全网向量索引,爬虫舰队+新鲜度=搜索商护城河);**能力定价应按不可替代性分层**——DeepSeek 定价结构(搜索按次计费与模型无关,查询侧摘要=副产品白送)正好符合此分层。

- **境内外权限不对称三律(2026-10-22)**:①**权限=管辖手段的函数不是配额厚薄**——境内服务器=全栈可达故全栈许可(ICP备案/等保/内容义务/日志留存/配合执法:管得了所以管得细,境内托管=进注册表领id接受全套poll门控,换境内经营合法资格);境外服务器=本体在管辖外只剩边境一个闸门(管不了本体只能管通路),通路侧黑名单非因宽容而因白名单化跨境=自绝全球互联网成本无穷大,fail-open是唯一现实选项——**名单类型跟管辖手段走**(问责按可达性分配律第三实例:手段全栈则fail-closed便宜,手段只剩闸门则fail-open被迫)。②**墙的功能是加价不是挡住**——境内白名单管**组织能力**(境内主体规模化先发牌),境外黑名单管**大众规模**(普通用户不为一个网站付翻墙成本);"境外默认通行"是设计出来的均衡不是漏出的洞;稳态黑名单但白名单模式存在过(敏感期局部/2009新疆断网十月=fail-closed全开)——**默认态是可调阀门不是宪法常量**。③**对价律:有名分有义务有救济vs无名分无义务无救济**——境内权限小但换名分(合法资格/法律保护/处罚有申诉通道),境外权限大但无名分(存在无法律地位,黑名单无申诉通道,被拉黑无处喊冤);**注册表深度决定权限也决定救济**:进注册表(领id)=接受谓词门控+获得身份,不进=无门控亦无身份;国家定价清楚:境内名分贵(义务重),境外自由便宜(但可被单方面抹除)。

- **个人项目托管三路线定价(2026-10-22 对价律的个人尺度实例)**:无敏感内容的个人项目,境外托管是结构性便利非"某种意义上"——零备案栈(ICP备案+80/443封端+UGC叠加公安备案全免)/零内容合规义务/成本地板低(GitHub Pages·Cloudflare·Vercel免费档+自定义域名=零元全球CDN)/部署即上线。对价:境内延迟150~300ms对20~50ms+晚高峰国际出口QoS降级;**风险是随机性非内容性**(无敏感内容只免主动上榜,挡不住共享IP邻居连带+SNI误伤,拉黑无申诉=无名分无救济);免费档默认域名有前科(vercel.app/workers.dev曾被限,github.io时好时坏)——境外路线须配自定义域名才稳。**第三条路=境内PaaS默认域名**(腾讯云开发等):备案义务由平台的伞扛着,境内速度+免备案,代价=平台规则约束+自定义域名仍需备案。三路线分档:境外VPS/免费档(免备案/慢偶断/无救济)vs境内PaaS默认域名(平台扛备案/快/平台规则)vs境内自有(全栈备案/最快/全栈义务)。**选择函数=读者在哪**:全球/自己/同温层→境外零税;境内大众且体验重要→平台扛伞或自备案;个人项目不做大众生意,名分用不上,故境外默认最优——放弃境内名分买回零合规成本。

- **代理费对价律+起诉投资函数律+武器攻击面配对律(2026-10-22 MC法律生态解剖)**:①**代理费买的是境内运营合法性不是字节**:外国公司不能直接在境内运营网游(L0外资准入),无版号连国区App Store都上不了(2020苹果清版号数万款下架,国际版MC手游彼时退出国区)——代理结构是制度性必须非"微软懒";网易对价包=版号申请资格+应用商店/支付渠道+商业化权(免费+内购大众市场,国服注册用户以亿计)+品牌赛事教育授权+**独家被许可人诉权**;国际版合法可得只覆盖有动手能力的少数,大众市场全在版号体系内——**投机点=灰色通道服务不了大众市场,大众市场必须买牌照**。②**起诉是投资函数律**:权利存在≠权利行使,行使=诉讼成本vs被保护收入的商业决策——迷你世界案实际原告=网易(独家被许可人)非微软,动机=保护国服营收,赔偿基准=中国市场;平行宇宙无代理→无国服收入→侵权照样存在(抄230元素事实不变)但**大概率无起诉:不是法律放过它,是经济学放过它**。③**武器-攻击面配对律**:每个主体有各自攻击面,每种武器需要对应诉因/通道,**谁能伤你=你的攻击面×对方手里的武器**——多玩盒子=破解客户端真实复制发行+商业化实体+应用商店渠道三攻击面全齐,网易律师函+商店投诉即下架(死因=三样全占);迷你世界=内容抄袭诉因成立,网易胜诉但2022广东高院终审**驳回停运请求**(赔5000万+删230元素,权衡玩家生态与比例)——**胜诉≠消灭**;PCL=无复制无修改无镜像(下载源=权利人自己的CDN,许可门在登录)+个人开发者+不走应用商店+微软默许第三方启动器(离线模式官方内置,启动器喂养正版销量),**网易无诉因可配——不是不想告是没有可诉的**;家长武器=举报(行政通道零门槛无利害关系要求,未保是政治最高优先级受理类别),恰好命中PCL唯一攻击面(未保闸门轴)——**民事武器配不上就民事不动,行政武器配得上就行政伤它**。

- **中国软件分发再集中化六成因(2026-10-22 答"去去中心化趋向成因")**:全球基线(商店=身份层+发现层+收租层)中国全有且更极端,中国特有六加成:①**治理设计=最深变量**:集中=可枚举=可治理,窄腰律在此是主动建筑学非碰上——2023 工信部 App 备案制(App 像网站备案,商店核验),小程序/SDK/快应用逐层备案,监管在枚举软件栈每一层;商店从商业设施升格为**软件分发的 poll 门**(无备案不放行),去中心化分发(链接发 APK)=监管最恨的不可枚举尾巴,从此不只难用是不合规。②**信任崩塌史更惨烈**(下载站全家桶/假官网产业级,2345/快压/p2p下载器,用户被烧更狠→守门人需求更强,免疫需求强度与病史成正比)。③**移动蛙跳**:几亿用户首台计算设备=手机,世界观从第一天="软件从商店来",PC 官网下载文化在中国从未长成主流——去中心化分发连文化根基都没有。④**超级应用收编=集中化终极形态**(微信小程序 2017 跳过下载本身,软件活在平台注册表,分发支付身份发现四合一;商店还分货架,超级应用只有一张注册表)。⑤**厂商硬件层收费站**(Google Play 缺席→华为小米OV商店割据,"未知来源警告"拦侧载引流;游戏渠道硬核联盟抽 50%,苹果 30% 都显得温柔,渠道税=中国移动互联第一税率,开发者不接渠道到不了用户)。⑥**获客 Fraud 经济学**(低信任环境去中心化获客漏斗被假站骗子打烂,信息流+商店分发反而便宜)。**收口判断:全球商店化=商业进化;中国再集中化=商业进化×治理设计的合力**——商店在中国不只是免疫系统还被国家征用为治理窄腰(实名/备案/连坐三层);西方集中=市场均衡可被反垄断撬开(欧盟 DMA 逼苹果开侧载),中国集中=均衡+法规双锁,曲线更陡无回头路。**诚实补笔:灰色尾巴没死**(QQ群 APK/Gitee Releases/MC 启动器生态——PCL 自己就是去中心化分发活样本:官网+爱发电+群文件),结构仍双峰只是主流全收编尾巴缩进同温层——和墙的所有故事同一形状。

- **法律分类学=窄腰拓扑学(2026-10-22 答"app与网页备案分治莫名其妙")**:①技术观察成立:纯静态页→SPA→WASM→PWA→Electron→WebView壳→原生app→OS=**一根连续轴,没有任何点能划出app与网页的界**;"exe依赖也要备案"归谬法成立(形态定义会炸掉整个编程业)。②**法律的功能定义其实已经载体中立**:备案管的是"通过互联网向用户提供信息服务"这个功能,不挑载体(网页/app/小程序/API全在内);exe归谬失效的真正原因=依赖库不向用户提供网络服务,**功能定义直接排除,不需要形态学救济**。莫名其妙感来自实施层:备案=注册表,注册表必须挂在窄腰上,而**窄腰按载体分形**——网页窄腰=域名+境内托管(2000 ICP备案),app窄腰=应用商店(2023 App备案商店核验),小程序窄腰=平台,生成式AI窄腰=模型服务上线(2023算法备案);**同一部功能法,每出现一个新窄腰长一张新注册表**——APP与网页分开备案≠两种行为被定性,=一个功能定义钉在两个窄腰上的两张表。法律概念跟着窄腰走不跟技术本质走=问责按可达性分配律的**定义学形态**。③**一切分类都是带目标的压缩(立法)**:32GB内存确有2^(32G)种状态,任何能用的类型系统都必须压成几个桶;问题从来不是"桶真不真"是"压缩的目标函数"——类型系统压向编译期不变量,模态轴压向合成器能消费什么(分表=轴上选切点),**法律压向可治理性**(桶必须可枚举/可裁决/稳定,逼真度为吞吐量让路=斯科特《国家的视角》legibility);法律的定性不是哲学错误是**治理的采样定理:采样率由执行带宽决定不由现实分辨率决定**。④**载体套利律**:按载体划线有结构性漏洞——本质不变换壳即出圈(PWA装网页绕App备案,小程序当年钻"不是app"空子);**按载体立法=永远追补丁,按功能立法+按载体建表=中国实际形态**:功能定义兜住本质(跑不掉),载体注册表兜住执行(抓得住),补丁周期=这套架构固有成本。收口:**莫名其妙=功能定义(载体中立)与实施注册表(载体分形)的张力;法律不是把连续体误当成几类东西,是把连续体钉在几个够得着的桩上;桩的位置由窄腰决定不由本质决定——预测下一个备案对象,不看技术形态,看下一个成形的窄腰**。

- **App备案解剖(2026-10-22 工信部105号文+官方咨询答复一手源取证)**:①**双备案不是双重定性是两个对象各挂各的窄腰**:官网(域名+托管)→网站ICP备案(2000起),App本体→App备案(2023起),同一主体两表都登记;法规结构=同一功能定义("境内从事互联网信息服务")钉在两个窄腰上的两条登记。②**备案本身同重量级**:官方原文App备案"参照网站备案的方式",同一工信部系统(ICP/IP/域名备案系统),接入商或分发平台代提交→省管局20工作日→备案号;"app较重"体感来自备案外的叠加栈(商店审核/SDK清单/权限/个人信息合规);真正重量分水岭=经营性轴(非经营备案轻个人可办 vs 经营性ICP证/EDI证重要公司要资本),对网站app一视同仁。③**单机不联网APP/小程序无需备案**(工信部咨询答复原话,nmca.miit.gov.cn一手源);渠道指引把"单机"解释得更宽:完全离线型/仅广告联网/仅登录验证联网都算单机,**只有业务真跑在境内服务器上才触发**——功能定义再次是裁判载体不是。④**文本全覆盖执行抓手可枚举**:抓手=分发平台核验(无备案不上架)+接入商核验(境内后端不给接网);上架商店=两抓手都咬;官网分发+境内后端=接入商抓手咬;官网分发+境外后端=两抓手落空=事实灰色尾巴。⑤**"App"=移动互联网应用程序(含小程序快应用),PC桌面exe不在注册表里**——PCL这类Windows软件无备案制度,监管对桌面载体只有净网式打击(木马全家桶)无备案制;**载体注册表律实证:注册表永远后于载体出现,出现之前该载体活在灰带**(桌面软件灰带存续至今)。

- **功能测试判自家两案+工具服务分离律(2026-10-22 应用备案框架到Cutrans)**:①**官网源插件下载 vs 自动更新:管道同构≠功能同构**——两者都是客户端向自家服务器GET一个blob,但备案的功能测试问"端点向用户提供什么":版本检查/更新元数据=元数据查询(与"仅登录验证联网"同档,渠道指引归入单机豁免);**插件下载=功能/内容分发**(用户装完得新能力,服务在服务器上延续)=互联网信息服务本体=触发档。同一GET不同定性,功能定义载体中立律在自家项目生效。实操:插件服务器在境内→该端点至少网站ICP备案,App若上架境内商店再叠加App备案核验;境外+官网分发→两抓手落空=灰色尾巴;**底牌:PC桌面exe没有注册表**(App备案管移动互联网应用),Cutrans桌面形态+不上架境内移动商店→备案实际不沾身。②**BYO-API的agent loop不触发备案**:功能测试=**谁向用户提供了网络信息服务**——我们供的是工具(agent loop能力),网络服务是用户自己配置的端点供的(OpenAI/本地Ollama/自建网关);浏览器不为所访问网站备案,curl不提供网络服务,PCL不提供游戏文件(文件在Mojang CDN)——**备案看"你向用户供服务"不看"用户经你访问服务",方向相反义务主体不同**。**工具服务分离律:工具提供者在功能定义外,服务提供者在功能定义内**——PCL灰带生存同款法律形状。③**未来红线**:上线自营模型网关/默认端点给用户用=那一刻变成服务提供者,备案触发且叠AI专项表(2023生成式AI算法备案);**工具形态=零备案义务,自营服务端点=备案+AI专项;保持BYO=保持在定义之外**。

- **桌面移动分治律=窄腰覆盖率差(2026-10-22 答"为何电脑应用和手机应用被分开")**:分开非按技术本质(都是软件同一连续轴),按**执行杠杆完备性**分。移动端窄腰全栈境内化(小米备案指引实证工信部组织三类主体:接入商+分发平台+智能终端生产企业):分发闸=国产商店全境内主体可核验问责(**Google Play缺席反而帮忙:真空被国产商店填满,分发层全国产=全可管**)/设备闸=国产OEM系统层可拦截未备案应用(Windows无此闸微软够不着)/接入闸=境内云核验/支付闸=境内支付轨——四道闸全在境内主体手里,注册表立得住。桌面端无窄腰:分发=全球互联网直发(官网/网盘/QQ群/BT/Steam/GitHub)无境内闸门;唯一窄腰时代=下载站时代,处理方式是净网式打击非备案,打完下载站萎缩桌面分发再没集中过;桌面备案=无核验者无拦截点无连坐对象——**立法者不给执行不了的窄腰立法,立了也是空文**。风险时代差:App备案法律依据=反电诈法,电诈隐私滥用主战场在移动端,监管跟风险质心走;桌面危害时代(木马全家桶)已过。**判决:桌面"不用备案"≠被豁免,=桌面从未长成可执行的窄腰故注册表从未出现——灰带第三成因:无闸可建的灰(前二:够不着的灰/没人举报的灰)**;对Cutrans的利好性质=**残余红利非权利**,窄腰一旦在桌面再成形(国产Windows商店/PC微信超级化/统信麒麟商店普及)注册表立刻跟到(小程序实证:窄腰2017成形表2023到)——**预测义务降临:不看载体看窄腰**。

- **游戏三重身份律+实质审查边界律(2026-10-22)**:①游戏第一身份不是app是**网络出版物**(出版总署体系,2018起归中宣部NPPA)——app=工具/服务→备案制(事后登记),游戏=内容/出版物→**出版管理(版号=事前审查)**;中国内容治理把一切内容(书/影视/游戏)视为意识形态载体,意识形态必须事前审。**义务栈=三层继承+两层特殊**:软件服务层(App备案,继承)+文化内容层(版号+内容审查,特殊)+成瘾消费品层(防沉迷+实名+时长,特殊);防沉迷只是最显眼层,版号才是大头(无版号运营游戏=违法,套版号换皮被打)。修正"单机也要防沉迷":境内正式渠道游戏(含单机/国行主机)一律要版号,防沉迷实名接入=版号审批运营条件,执行面落在网络游戏运营企业,纯离线单机无执行面故约束前移到审批环节。Steam国际版/PCL免疫=桌面(无注册表)+境外(够不着)+PCL是工具(功能定义外);蒸汽平台=对照组(合法路径存在但只有百来款过版号——**版号稀缺性=内容闸收紧度**)。②**判断是不是游戏:实质审查定定性,载体决定管辖**——实质审查看玩法闭环(规则/目标/胜负积分/虚拟经济/交互娱乐),版号审核真人审内容;**工具用形式测试(便宜),内容用实质审查(贵)——内容承载意识形态,国家愿意为意识形态付审查成本**。剪映手机版=无玩法闭环产出视频文件=工具;**"只有剪映功能的MC模组":在MC内分发→继承游戏载体整套制度(网易版走平台审核,UGC寄生平台版号不单独要);拆出来单独当app发→按自己面目受审=剪辑工具不要版号**——同一本质不同载体不同制度,法律世界没有"本质是什么"只有"在哪张表上以什么面目被审"。③边界连续体的补丁:游戏/工具边界连续(寓教于乐/健身环/绘画app),备案边界=形式测试,版号边界=实质审查;套利反套利在此层发生(小程序游戏逃版号→2018后收编;换皮套版号→专项打击);**意识形态领域采样率无限提高=采样率由执行带宽决定律的唯一例外**。
