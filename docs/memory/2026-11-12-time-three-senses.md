# 2026-11-12 时间三分：时间线不是底层概念（v4 内存模型 ADR 的一节）

## 起因

- 用户的疑问：时间线这类概念，配不配作为底层概念？还是只该当作一种参数？“根本不存在纯粹的视频，时间感都是模拟出来的”。
- 用户同时担心，一直追求纯粹性可能是个无底洞，并指出 Blender 这样纯粹的 API 也引入了时间线概念。
- 用户已确认把本结论作为 v4 ADR 的一节记录。

## 结论（由既有宪法推出，Claude 整理，用户认可记录）

“时间”是三样东西，不能混成一个词：

| 叫法 | 是什么 | 归属 | 依据 |
|---|---|---|---|
| 序数时间 `t` | 第几帧、共几帧 | **核心**（流的自变量） | [流协议](03-stream.md)：`Stream{frames, get(t)}`，“流只带顺序时间” |
| 度量时间 | 秒、fps、时间码 | **制式与参数**，归消费者 | 流协议：“fps 的家在预览器、导出器（度量时间的唯一消费者）”；[模态与制式](05-modalities.md) |
| 时间线 | 轨道、片段、播放头、剪辑手势 | **编辑器**，即 App 投影 | 只是对聚合参数的可视化编辑 |

- **“片段在时间线上的位置”就是一个参数**：即聚合输入的相对时间 `t`（[树的声明](04-declarations.md)：“聚合被层级、相对时间、相对位置、缩放、透明度完全描述”；现有代码中 `AggIn.t` 是它的雏形）。
- **“不存在纯粹的视频”恰好是设计依据**：核心不建模“视频”，只建模以 `t` 为自变量的流。“流逝感”是播放器这个消费者的事。
- **Blender 印证同一分法**：当前帧、起止帧和帧率是场景属性；F-Curve 是帧到参数值的函数；“Timeline”只是众多编辑器类型之一；视频序列里的片段是带起始帧和通道的数据。

## 纯粹性的止损规则

- 用[身份宪法](02-identity.md)第 6 条的元规则判定，**不问“它在物理上存不存在”**：
  - 规则对任意类型都成立的，进核心；
  - 只对某一类成立的，做成数据或插件；
  - 只对某个场景成立的，交给调用方的策略。
- 本例的判定：
  - `t`：视频、音频、参数流都成立；静图是对任意 `t` 返回同一帧的常量流，也成立。因此进核心。
  - 轨道式时间线：节点合成不需要轨道，因此是编辑器。
  - 秒与 fps：只有消费者需要，因此归制式。
- 每个概念只判一次并记录；只有出现新证据才重审（[认知更新律](00-reading.md)）。

## v4 需要落实的点

- 节点按 `t` 求值；聚合输入带相对时间偏移。
- 时间线编辑器不进内存模型，作为 App 投影。
- 现有 `vne/documents.zig` 的 `Document` 自带 `fps` 字段，与“fps 归消费者”的宪法不一致，需要在 v4 中明确处理：要么把帧率移出文档、归入制式，要么说明保留它的理由。
