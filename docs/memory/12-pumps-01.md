## 十一、触发与泵

- **函数=闭世界(100% 预判可代表),触发=开世界(不可预判只能等待)**;闭集直写 switch,开放集才要指针表。
- **触发三件套**:函数指针(函数是值)+注册表(订阅)+emit(触发遍历调用)。**好莱坞原则**:GUI=控制反转(你注册,系统调你);CLI=你主动。
- **栈 vs 队列**:栈=LIFO 调用嵌套(谁挂起回哪去,同步,返回即死);队列=FIFO 任务排队(还有什么活,异步,处理完才死)。**函数调用=同步通知(栈);通知=异步调用(队列)**;消息队列=异步世界的调用栈;随时性编码=队列缓冲+泵睡醒。
- **泵形态学**:阻塞泵(GetMessage 睡到消息来,零占用)/忙等泵(PeekMessage,永有活干才合法)/节拍泵(超时等待,醒于事件或节拍)。**while(true)=不设先验退出**(结束是事件不是条件);循环无速度,速度归最慢站;主循环=状态的命。
- **CPU=纯流脚本无泵;OS=大泵**(调度循环+中断);程序=默认脚本(借 OS 泵),交互程序自写内泵。**泵对用户直觉(人是事件驱动),脚本对程序员直觉(顺序可推)**——语言默认脚本(零运行时),框架默认泵(伺候交互)。
- **多泵=多线程**(每泵一线程一栈,OS 交错);协程=单线程多逻辑泵。检测泵(管何时)与消费泵(管干什么)分家;消费泵=睡到有活(popBlocking)。泵上纪律=限时切片,长任务甩工作线程,泵只分派。
- **消息纪律**:发令=push 纯告知;接令=订阅自取;行动=存入器内政。
- **UI 解释器=纯函数** f(事件,上下文)→命令:可测/AI 直通(跳过解释器直接发命令)/可录制回放。行业名词:物理事件(InputEvent)vs 语义命令(Qt QAction/Godot Action/Unreal InputAction/Redux action);架构名=命令模式/命令总线/CQRS/事件溯源/动作映射。**UI=输入插件之一,AI 是另一个;一切触发终归内存命令**。翻译归中央(一次翻译全体享用;分散翻译=N 倍重复+上下文分裂)。
- **UI 输入分层与泵的归属博弈(2026-10-10)**:WebGPU **无事件**(纯 GPU API,输入不归它;浏览器里归 DOM,原生归窗口层 winit/SDL/Win32);粗粒度事件(双击/拖拽阈值)=UI 工具箱内政(ImGui 的 io 自带双击时间/位移阈值——借它的或自写皆可,自写就几行:时间窗+位移窗)。分层:OS 事件→窗口后端→工具箱 io→UI 解释器(翻译)→内存命令→命令环。**泵归属博弈真实存在且是 UI 史的主权战争**:谁拥有主循环——框架(Qt/GTK/Cocoa/Android/浏览器/Node 全是你注册回调它泵)vs 你(ImGui 即时模式:你泵它答);我们宪法:UI 插件自带泵,核永不拥有。**ImGui 即时模式与宪法同构(2026-10-10)**:zgui 只带语义(点击/双击/拖拽判定),零泵零回调——泵=开发者的帧循环(每帧 NewFrame→控件→Render);OS 事件接入归平台后端(翻译成 io 状态);**控件不持久、每帧重声明=一切皆投影同构**(UI 是每帧重建的投影,不是长命对象树)。
- **泵语言谱系**:Erlang(进程+信箱,泵的原生语)/Smalltalk(一切皆消息)/Node(运行时=泵)/Go(goroutine+channel)/LabVIEW(数据流)/Qt 信号槽——泵语言全带 GC(事件寿命不可预判→GC 兜底);**Zig 证伪对立**(显式所有权+arena+寿命纪律=泵与金属性兼容)。我们的形态=Erlang-lite。
- **触发溯源链与物种分工(2026-10-10)**:一次性函数=兵(干一次就走),队列=传送带(不带动力,缓冲+闹钟 condvar),泵=工人(睡到有货)。交流拓扑:函数→泵=往队列扔纸条(push+signal);泵→函数=分派 switch 到处理函数(借泵的线程同步执行);泵→泵=各自信箱互投;函数→函数=直调。**触发的终极来源=硬件中断(鼠标/键盘/网卡/声卡 IRQ)+定时器(时间本身)**:中断→OS 大泵→我们的 UI/IO 泵睡醒→UI 解释器翻译成内存命令→命令环→工作泵→一次性函数干活→完工回执环;泵内可再发令(链式接力),一切触发的根=中断与时钟。**锁×环正交**:环答槽位怎么摆(形状),锁答谁能碰(纪律);std.Io.Queue=有锁环(mutex+cond),热路径=SPSC 无锁环(内存序),教学版=有锁非环(ArrayList)。
- **scanf 陷阱(2026-10-09,教育批判的具体病灶)**:CS 第一课把 printf/scanf 摆成对称("一个收一个写"),但 printf 是闭世界(100% 预判),scanf 是开世界——它是披着脚本外衣的泵原语(无输入时进程被 OS 挂起、睡等键盘中断;泵藏在函数实现里,定义里看不出来),教材连作者自己都信了这对称,第一课就断送了泵认知。更狠的是 scanf 提供了**假交互**("看,它会问你输入!"),反而让学生连"我的程序和浏览器/游戏为什么不一样"的问题都问不出来。根因不止"好考核":考核基础设施本身是脚本形的(OJ=喂 stdin 比 stdout,时间没法评分),评测机器再生产了误解。后果:学生眼里程序=黑框框敲算法;从黑框到游戏的距离不是更多算法,是一个从未被点名的概念(循环泵)。控制台本身就是化石:电传打字机时代的抽象(stdin 行缓冲=终端的行编辑泵在替你干活),你的 main 从一开始就是 OS 大泵的一个回调——连"纯脚本"都活在泵里,没人告诉他们。
- **载荷统一律(2026-10-09,用户表述)**:传递纪律在同步/异步两个世界相同——**算必触体,故传只传壳**(指针/身份);算的时候本来就要全看一遍,传的时候再全传一遍=白搬。异步化=同步调用+时间随机化,机制增量只有两样:队列(缓冲数组)+泵(睡醒),核心传递思路不变,变的只有时间维。**但时间随机性逼出一个衍生纪律:载荷须活到被消费**——同步调用的寿命由栈帧担保(调用者睡着等着),异步没人担保,只能靠纪律:故消息只带身份(身份不悬空,指针会悬空);GC 是别的语言对同一问题的另一种交卷,Zig+身份纪律是我们的交卷。栈帧=确定时间轴上的借条,消息=随机时间轴上的借条;传递永远是传借条,不是传货。
- **排队寿命三保(2026-10-09)**:命令排到队时,所指之物还在吗?不靠调度合理性,靠三层机制:①**身份语义**——消息指内容不指位置:(流,t) 由声明唯一决定(幂等律),所以最坏情况=查无此帧(安全降级),**永不指错帧**;位置型身份(槽位索引)才有 ABA 病,这正是"按号索引删、不用位置启发"的原因。②**死亡律即保证**——以"存 t"流程为例:L2 完工前"L2 无"恒成立,帧被死亡律本身保护着,队列躺多久都不怕;通用情形(无此领域律的对象)=**先登记需要(lease)再投递消息**(lease-before-post,"先压完再通知"的推广)。③**可再生性兜底**——帧=f(树),死=重算,不是事故;这是剪辑系统比通用系统奢侈的地方(文本/数据库的内容不可再生,它们才被迫值拷贝/共享所有权/GC)。载荷三分法:小物值语义、可再生物身份、不可再生大物租借。**调度只影响快慢,机制保证对错;好系统的标准:调度只能变慢,不能变错。**
- **地址空间即通信宪法(2026-10-09)**:线程通信的自由来自**共享地址空间**——四种形态任选:直调(同步)/加锁直读(查询)/自建队列(命令)/原子变量;指针有效,体可免拷贝。进程通信默认=内核队列(管道/socket):序列化+用户→内核→用户两次拷贝,**指针跨界即失效**,只能传值/身份;但"只能排队"不完全对——**共享内存=手动开窗**(窗内只许偏移量不许裸指针,因为各进程基址不同;同步原语要跨进程版;队列也可自建在共享内存里不走内核;代价=隔离性让渡一部分)。所以不是先进 vs 落后,是**共享=自由+便宜+无隔离 / 隔离=约束+贵+有隔离**的对价;进程边界=崩溃与安全的最终容器(失败分层的地基)。MCP=JSON-RPC over stdio/SSE=内核队列+文本序列化,最重的一档,载荷必须自描述(永远传不了引用),换来跨语言跨机器可交换。**借条推论**:我们的"消息只带身份"让命令天然可跨进程(身份可序列化);但"传壳"在进程边界失效(壳里的指针过不去)——借条必须改写成自描述的票,货要么拷贝要么住共享内存拿偏移量;故多进程编排(启动器↔剪辑空间,Chrome 同构)一律:大数据住共享内存,消息传句柄。
- **通信的前提=缓冲+唤醒,不是泵(2026-10-09)**:异步通信的前提=缓冲区+接收方唤醒机制;泵只是最常见的唤醒形态(睡到消息来),同步调用的唤醒=返回(栈帧),硬件中断是另一种;发送方可以无泵(发完即忘)。**进程无选项律**:进程是 OS 执行一切代码的容器(地址空间+资源+至少一线程),纯脚本照样走 fork+exec+exit 全套——"脚本谈不上进程"是错觉,它只是短命;跑 python 脚本时,解释器本身就是那个进程。**socket=统一抽象**:本机 IPC 与跨网络通信同一套 API(open/read/write/close),差别只在地址族(AF_UNIX=文件路径 vs AF_INET=IP:port);端口=指针失效世界的门牌号——地址空间内用指针,跨界用门牌,借条上"哪儿提货"的命名体系不同而已;localhost(127.0.0.1)=网络格式在本机回环,先本机跑通再上网络几乎零改动。**服务器=永续泵,但泵可外包三级**:自己写(accept/epoll 循环)→框架写(Node/nginx 运行时藏循环)→宿主写(inetd/CGI/云函数——平台泵,你的代码退回纯脚本事件处理器,处理一次即退;CloudBase Event 函数同构)。
- **托管方统一论(2026-10-10,用户类比 QQ 中转)**:队列/信箱/缓存/中继服务器**同一本质=时间解耦的托管方**——通信/交接的双方不必同时在场,靠一个"永远醒着的第三方地盘"吸收时间差;进程内=内存环(内存没有睡的概念,永远醒,免费),跨设备=常开服务器(买 uptime,付费)。打电话=同步(双方必须同时醒);QQ 留言=异步(信箱托管:A 睡了 B 醒、B 睡了 A 醒之间的保管);信箱按设备分(每端一队列,与 SQ/CQ 同族),漫游/过期=托管保留政策。推论:一切缓存也是托管方——L1/L2 托管帧,让"产帧的时刻"与"用帧的时刻"不必同步。
- **调用不需要泵;引擎两派(2026-10-10)**:**直接调用=同步通知,调用方自带执行流,被调方零装置**——"监听消息"只在消息存在时才需要;流协议从不听消息,它是被动物件(泵的需求=时间解耦的产物,同步调用里双方时间重合,零泵)。**队列也没有泵**:队列=缓冲+闹钟(condvar=闹钟不是工人),泵=睡在队列上的消费线程的循环。行业引擎两派:①**对象被动+泵集中**(Nuke 拉式求值/游戏引擎 job system/Unreal RenderGraph/mpv 流水线线程)vs ②**对象即 actor**(Erlang 每 actor 信箱+泵/GStreamer 元件自带线程+显式 queue 元件);判据:**泵的数量≈并发域数量(UI/音频实时回调/工作池),不≈对象数量**。我们=①:流被动,泵集中少数长命;音频例外=声卡 IRQ 驱动的实时泵(硬时钟回调,行业通例)。
- **泵拓扑法(2026-10-10)**:**命令环按职责分(轨道/优先级类),不按 comp 分**;工人共享池跨流池化,消息自带流身份,工人自给自足调 get。每 comp 一泵=线程爆炸+全局优先级消失(违泵≈并发域律);每 comp 一队列=按身份不按职责拆(违表的先验)。例外:有状态启发器(t 依赖 t-1)需按流串行——解法=流内串行纪律(get 内部互斥/调度器不并发同流),**不是配泵**;将来若需按 comp 的 QoS 记账(公平/预算)才允许 per-comp 队列(YAGNI)。多工人扩展时按**工人**分队列(work-stealing 双端队列),不按 comp。
- **环泵配线法(2026-10-10)**:环与泵=**消费关系非所有权**——一环可多泵(MPMC 共享取,std.Io.Queue 即此),一泵可消多环(按优先级排干:先前台后闲时),绑定是政策配线不是结构焊死。**队列无消费者=死水**(缓冲的价值=有人收,泵是最常见的消费者形态);泵的睡眠对象=队列(消费泵,睡到有货)或定时器(节拍泵,睡到点儿)。**无限 comp 共享有限泵=复用(multiplexing)**:OS 调度器同构——N 个 CPU(泵)+按优先级分的运行队列(环)+无限进程(comp/流);流是任务,环是运行队列,泵是核。
- **内存命令泵解剖(2026-10-10)**:并发域=UI 泵+工作池+播放泵+音频硬泵(声卡 IRQ 回调,无 while,最硬形态:泵在驱动里,你的代码是回调);环=三轨命令环(前台点播/预判窗/闲时)+完工回执环。**工作泵解剖**:睡醒=总闸条件变量(任何环非空即响);取件=按优先级排干(urgent→window→idle);**惰性取消=身份失效即弃**(树改→旧流死→消息里的流 id 查无→安全丢弃,排队寿命三保的应用,不需 epoch 字段);分派=switch(kind) 直写跳表;链式发令(fill→产帧落 L1→发压缩令→完工回执);泵上纪律=限时切片(fill 以帧为粒度,范围预产=调度器发 N 条令,不霸泵)。播放泵=节拍泵(睡到下一帧 deadline 或回执先到,MsgWaitWithTimeout 同构)。
- **泵全插件化修正(2026-10-10,用户抓包)**:UI 泵/播放泵/工作泵**全是插件,不进核**——编辑=命令→分派→改树,同步完成,零泵;不浏览视频也能编辑(headless/AI 直发命令)是薄核的验收标准。**核心=命令分派表+同步执行+数据结构**(环的实现作为库待命,不强制在跑);**同步直派=栈(默认),环+泵=异步政策层(插件按需加载)**。泵插件各带各的:UI 插件带 UI 泵,播放器插件带播放泵,预产/渲染插件带工作泵,音频回调归音频输出插件。修正前"内存命令泵解剖"的总图错误地把 UI/播放画进了核心域——那些解剖仍有效,但归插件层,归何时加载由插件政策定。
- **树泵=核里唯一的泵(2026-10-10 二次修正,用户再纠)**:纯同步路径(嵌入式/AI 直调改树)可零泵;但只要编辑令走异步环——多源并发(UI 线程/AI 线程/MCP 外部进程)——就需要**恰好一台**核心泵:**树泵(真源管家)**:拥有内存树、单线程串行消费编辑令(免锁靠排队)、白赚**命令日志**(=撤销史+回放带+AI 审计轨,事件溯源;调试心智法的肉身)。宪法推导:真源唯一⇒编辑令必须串行⇒串行化点即泵;泵≈并发域——"文档编辑"是一个并发域,故一台;**全系统唯一被 actor 化的对象=真源自己**。退化形态:单线程场景树泵退化为同步直调(同一批 handler,零泵可跑)——泵是壳不是馅。其余泵(UI/播放/工作池)仍全归插件。
- **动树令与 ccmd;.cut 语言定位终版(2026-10-10,用户)**:修改树的命令定名**动树令**(edit commands),归树泵(全系统最快最轻的环);撤销史=.cut 代码的史(撤销管声明)。**.cut 定位终版**:.cut=纯声明(只有拓补关系,无执行序无触发逻辑);触发全在运行时(人/AI 经泵环发令);**语言自带交互=解释器预制泵逻辑**(特异性 JS:解释型+预制泵)——舍弃自造交互逻辑的自由度,换媒体编辑强先验。**ccmd=命令队列的伪代码投影**(队列双向投影成文本——cmake 把编译动作总结成清单的同构):预制的命令清单,触发 ccmd=依次触发这批命令;指令集越少=自动化越多=自由度越低(旋钮);远期:.cut/ccmd 嵌入游戏动画声明。

- **时钟物理律(2026-10-13 问答立法:最底层的 tick 是怎么物理实现的)**:四层——①晶振(石英压电谐振器=音叉,Pierce 振荡回路自激起振,Q 值高 ppm 级;RTC 表晶 32.768kHz=2¹⁵,二进制分频正好出 1Hz);②PLL 锁相环倍频(VCO÷N 与参考比相位反馈锁定,CPU 5GHz=25MHz×200);③时钟树(H 形平衡缓冲分配网, skew 是设计期大仗);④环形振荡器做非关键自激钟(频率随 PVT 漂,反过来当传感器用);原子钟/GPS/NTP 驯服系统时间。**一切泵的化归终点**:泵睡 deadline → OS 定时轮 → HPET/APIC 对自由计数器编程比较器(到期中断) → TSC 数 tick → PLL×晶振 → **石头的机械谐振**;整个软件塔的时间=数一块石头的颤抖。轮询守恒律在此现身:deadline 到期检查=比较器对 tick 计数器连续守望。OS 定时轮=按 tick 分桶到点换手的层级里程表,与二分阶梯日志同族(都按 2 幂分层)。诚实的底子:晶振也有 jitter/温漂——跨时钟域要同步器(亚稳态收税)、系统时间要 NTP 驯服、硬件要 watchdog;整个数字塔的时间是从有噪声的石头里判决出来的。
