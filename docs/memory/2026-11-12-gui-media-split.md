# 2026-11-12 界面渲染与媒体渲染分家（用户立法）

## 用户原则

- 有两种渲染，必须区分：**GUI 的 API 与绘制**，和**视频、图片等媒体的渲染**。两者都用 Zig 写渲染器，但侧重点不同。
- GUI 用 NanoUI。媒体渲染**不能用 NanoUI**，要**完全自研**。
- 用户的类比：AE 的界面是一套 UI 框架，特效本身是原生代码。
- Claude 的补充：严格说 AE 的界面用的是 Adobe 自家的界面框架，不是 Dear ImGui，但这不影响这条原则本身。

## 两侧的职责（Claude 整理，待用户裁定细节）

| | GUI 渲染（NanoUI） | 媒体渲染（自研，归 VM） |
|---|---|---|
| 目标 | 交互、排版、文字、状态反馈 | 作品画面：解码、求值、合成、效果、编码 |
| 正确性标准 | 好看、跟手、可读 | 像素精确、可复现，同一声明得到同一指纹 |
| 时间 | 界面帧率，按事件重绘 | 作品时间轴与制式，与界面帧率无关 |
| 归属 | App 与 Shell 的投影 | VM 的真源计算，见宪法“声明唯一真源” |

- 两侧唯一的接触面是**帧**：VM 产出的预览帧，由 GUI 以纹理形式显示（现在是 Preview ABI 交付的 BGRA，见 [Preview ABI](2026-11-10-preview-abi-contract.md)）。此外，GUI 可以拿到 VM 算好的**数据**来画界面叠层，例如波形峰值、示波器、变换手柄的坐标。
- 叠层（选择框、手柄、参考线）由 GUI 画在 VM 帧之上，属于界面；示波器、直方图这类分析结果由 VM 计算，GUI 只负责绘制。
- 由此，NanoUI 缺少混合模式、滤镜、遮罩，不影响作品画面，因为这些属于媒体渲染一侧。

## 现状核对（2026-11-12）

- 已守住：`tools/verify_architecture.py` 禁止 `runtime` 导入 NanoUI；文档预览由 VM 求值，GUI 不再自己运行预览 DAG。
- **灰区**：`consoles/gui/vm_client.zig` 的 `previewAsset` 和 GUI 侧的 Source 读取，用共享的 `imaging` 模块在 GUI 里**本地解码 PNG**。这是 2026-11-07 C1 片定下的“GUI 获取 owned Source 字节后本地解码”。按本原则，媒体解码应归 VM，GUI 只接收已解码的帧。待定：改为由 VM 交付已解码的素材预览帧，或明确把“缩略图级解码”列为允许的例外。
  - （同日补充）用户随后指出，素材预览本身是一个功能性插件，应当自渲染像素，见 [App／插件界面模型](2026-11-12-app-plugin-ui-model.md)。因此方向是由预览插件负责解码，GUI 不再解码，不设例外。尚未实施。
- 编辑器里 RGBA 到预乘 BGRA 的转换属于显示适配，留在 GUI 一侧合理。
- 媒体渲染器本身目前只有 `runtime/render.zig` 的 CPU 逐像素求值，真正的自研媒体渲染器尚未开始，将建立在 v4 内存模型与流协议之上。

## 待定的接口决定

- **媒体侧的 GPU 后端**：CPU 参照实现先行，GPU 后续再加；参照 FilmCraft 和 EffectCraft 的“CPU 参照答案 + GPU 对比测试”做法。
- **零拷贝显示**：NanoUI 已能直接显示应用自己的 `ID3D11Texture2D`（见 `third_party/nanoui/src/ui/d3d11_video.zig`）。如果媒体渲染用 D3D11，或能导出共享句柄，预览帧可以零拷贝交给 GUI；如果用 Vulkan 或 D3D12，需要设计互操作方案。这是媒体侧选型时必须一起考虑的约束。
- **依赖方向**：媒体渲染器不得依赖 NanoUI；GUI 不得依赖媒体渲染器内部，只依赖帧与数据的交付契约。
