- **理解门控游标律(2026-10-13 用户立法)**:①消费方能力边界:预览窗口=[自己的游标,产方写游标)——可读止于最新消息,可写止于自己的游标且只进不退;②**游标移动以理解为条件**:机器只在探测到能理解的指令后才移动游标,不理解的指令游标纹丝不动——两推论同立:**多机扇出天然按角色分工**(同一条广播流,懂的前移不懂的留原地,无需路由表,分工是消费语义自带),**"两个外机动一个游标"从定义上不存在**(每个游标只有一个主人且只在主人理解时前进,读侧争点直接消解);③**无人能懂的消息永不移动=停滞即红标**:一条指令所有机器都不懂→没有任何游标越过它→天然停在原地,超时/巡检即现形,正好接 command.on_unknown 未知命令通道——**未知命令的处理从意外变成结构(不懂=不消费=可观测停滞,不被误吞不误执行)**。行业亲证:硬件中断同拓扑——驱动只 ack 自己处理的中断号,不认的留在 pending 等主人。

- **游标读写协议(2026-10-13 问答立法)**:**写侧=release 纪律**:先写消息内容再推进写游标——内容写完且可见才许发游标;反序(先推后写)=消费者读到未写完的垃圾槽。**读侧=执行先于推进**:读→理解(不懂则游标不动,理解门控律)→执行→推进游标,**推进与执行同一 tick 提交**;**先推进再执行=at-most-once 静默丢失**(崩溃窗口:游标已过消息没执行,永不重读无人知——静默丢失永远比可去重的重复更坏);执行完再推进=at-least-once,重复可去重(幂等/序号游标)。**合法的先推进形态=认领式**:先把消息拷进自己的动作树(所有权迁移),再推进游标,之后择机执行——消息已住进自家树,队列那份只是剩壳(工作队列标准做法,与"动作树=安检后的工位"合流)。完整读侧协议:**读→理解→执行或拷入自家树→推进游标,同 tick 提交**。

- **聚合器与制式特化(2026-10-14)**:聚合器输入口数必须定死(2/4 个都行,不许变长),不够就加新机器或选更大上限机器(FL 100 轨上限=同款粗暴);**一轨一帧**(换到视频=一轨一视频),保证输入口数恒定;**时间重合≠空间重合**:传统剪辑强行把"同轨时间拉长会撞后段"当规则是病——时间和空间重合是两件事,另一台机器管,跟帧聚合无关。
- **独立泵+定长缓存的硬件亲证(2026-10-14)**:驱动引擎就是这个形状:定长缓冲+独立 IO 线程——三原因:硬件驱动有**物理距离**(寄存器 L123=CPU 物理上够不到那么远,所以要专属近空间)、有**多用户访问**(必须独立泵)、有**硬件时序**(各自硬节拍)。播放器泵=连接调用所有合成机器;虚拟引擎=连接调用播放器;真实引擎后议。

- **类PS 先行=宪法验收场(2026-10-14 用户立法,行动顺序)**:先做类PS(图像编辑)——**全定长零时间复杂度**,把宪法全部机关(独立泵机器/机器 id/内部唯一帧定长空间/以查代算(希望 id)/命令环/撤销日志二分阶梯/id 寻址/启动器→编辑空间薄壳→核心 dll)在最简形态证对,不付视频特殊成本(多帧时序/A/V 同步/2048 采样窗/变长压缩/二级压缩/时间轴轨道逻辑)。**验收场景(最小完整闭环)**:`加载图片(定长像素帧)→调色效果器(结构帧:色温/饱和度/亮度)→饱和效果器→导出`——一条 comp 验收:以查代算(改参数只重算该链不相关分支)/独立泵(两台效果器实例各自泵)/机器 id 寻址(函数指针+唯一帧同址)/撤销(改参数=增量进日志可回放可撤)/启动器发命令→薄壳→核心 dll 建 comp。**视频=时间轴插件维度不是重写**:源机插件(解封装/解码)按时间戳产定长帧窗/编解码器插件/A/V 平行模态/制式也进插件——核心模型一字不改,"加几个效果器插件或逻辑就能推出来"不是乐观,是架构做对后视频只能这么长出来。**先别动,先想**:下一步把类PS 验收场景 comp 结构(效果器实例/帧格式/参数结构帧/希望 id 关系)写成一纸最小规格再谈动工。

- **整体性判据=以定长为基础结构的重复(2026-10-14 用户立法,自我修正)**:人判断"是不是一个整体/一种类型"的标准不是定长,而是**由固定基本单元重复组成**——视频=帧×N(帧定长,N 随意),图片=像素×w×h(像素定长,w/h 随意)。**基本单元定长,数量随便变**——定长是充分不必要条件,不是必要条件;变长不是随意,是有确定规律有最小基本单元的变长。
- **变长=声明可变,地址定长(2026-10-14 用户立法,AE/剪映 实测形态)**:帧地址在**合成创建/加载时一次分配好**,之后永不因裁剪变动;帧长/裁剪范围只是**声明层元数据**,唯一客户是 UI(红线框/可点选区/鼠标命中范围);计算永远在定长缓冲上跑(哪怕声明里裁了)。**显示是声明的投影,计算是定长的兑现,两者解耦**——裁剪/复原=改声明不是改地址,所以没有地址释放后的垃圾/不连续/只能赋空白;复原性满血。**制式=上限预设**(1080p/2k/4k 是 cap 不是离散格式),声明层只存"用户裁到了哪"。**下策勿取**:先读声明位再定 for 次数——把代码区常量降级成堆中变量(先验降级),且地址不连续+垃圾化+不可复原。**与宪法老账对齐**:制式住声明层运行时消失;声明永远不改内存,内存分配与生命周期是独立机关。
