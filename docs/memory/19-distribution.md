## 十八、分发四物、OS 依赖轴与新旧 VM 路线(2026-11-02 调研定案)

- **分发四物**:Host/安装器、不可变 VM Pack、按 OS+CPU 的 Native Runtime Pack、用户 VM Session。VM Pack 只含声明、策略、资产与能力清单,不是内存快照;Session 包含文档、History、Task、布局和当前 Pack 选择,安装/更新/卸载不得覆盖。默认核心离线可用,Zig 不属于用户运行时,大 Runtime 按需独立下载。
- **三形态与验证环境**:编译产物只产分发物且不写应用状态;便携版数据在程序旁;安装版程序在系统目录、数据在用户配置/状态目录,注册表/文件关联/卸载归 InstallPort,卸载保留数据。验证 Session 是第四种临时环境,不与任何日常环境共享目录、链接或缓存;`diag-user` 已改为资源目录与独立验证数据根分离,config/state/cache/runtime/pack 的完整分根仍待后续。
- **OS 与 CPU 两条轴**:Semantic Core、VM Pack 与规范 Session 尽量跨 OS;Window/Input/File/Process/Credential/Install/Clock/GPU 归窄 Port;Native Runtime 按 OS+CPU 分包;安装器各平台各做。跨平台的是语义,不是像素、原生窗口行为、安装机制或安全边界。旧 `source/ui` 领土命名逐步映射为 core/ports/native/installer/session,不搞一次性大搬迁。
- **Windows 正源规则**:文件关联走 ProgID 与 `SHChangeNotify`,卸载清理自身 ProgID 但不误删其他应用可能接管的 Default 值;Known Folder 取目录;Job Object 管进程树;Credential Manager 管凭证。正源=[File Types](https://learn.microsoft.com/en-us/windows/win32/shell/fa-file-types)、[Known Folder/CSIDL](https://learn.microsoft.com/en-us/windows/win32/shell/csidl)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[CredWriteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew)。
- **Linux/freedesktop 正源规则**:`DATA/CONFIG/STATE/CACHE/RUNTIME` 分根,undo history/layout/open files 属 STATE;入口用 Desktop Entry,关联用 MIME Apps,沙箱资源访问经 Portal,Wayland Surface 与 xdg_toplevel 分层,凭证走 Secret Service。正源=[Base Directory](https://specifications.freedesktop.org/basedir-spec/latest/)、[Desktop Entry](https://specifications.freedesktop.org/desktop-entry-spec/latest/)、[MIME Apps](https://specifications.freedesktop.org/mime-apps-spec/latest/)、[Portal](https://flatpak.github.io/xdg-desktop-portal/docs/)、[XDG Shell](https://wayland.app/protocols/xdg-shell)、[Secret Service](https://specifications.freedesktop.org/secret-service-spec/latest/)。
- **macOS 正源规则**:Host 与资源分别住 bundle 的 `Contents/MacOS/Resources/Frameworks/PlugIns`;文档类型用 `CFBundleDocumentTypes`;签名/公证后不向 bundle 内下载替换插件,可更新 Pack 放外部受管位置;凭证走 Keychain。正源=[Bundle Structures](https://developer.apple.com/library/archive/documentation/CoreFoundation/Conceptual/CFBundles/BundleTypes/BundleTypes.html)、[App Sandbox](https://developer.apple.com/documentation/security/app-sandbox)、[Keychain Services](https://developer.apple.com/documentation/security/keychain-services)。
- **JVM/Wasm 新旧路线衔接**:[JVM 规范](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-2.html)证明规范语义可与实现布局/GC/JIT 分家;[jpackage](https://openjdk.org/jeps/392)证明仍需各平台原生安装器;[JEP 411](https://openjdk.org/jeps/411)警示不要扩张进程内权限系统,完整不可信运行时优先进程外隔离。[Wasm Core](https://webassembly.github.io/spec/core/intro/introduction.html)与[Wasmtime Security](https://docs.wasmtime.dev/security.html)给出显式 imports、内存/控制流边界与 capability 文件访问。
- **不造大 JVM**:现行 `.wasm → 安装期 AOT → 原生 .cop` 仍是可信性能档默认,新增调研不推翻该路线。常驻沙箱档将来需要时再评估成熟 Wasm 运行时;原生不可信插件直接走 OS 进程隔离。CCB/CUI 保持声明闭集,不为了“像 Java”另造通用 ISA。
