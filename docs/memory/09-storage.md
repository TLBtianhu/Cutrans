## 八、物化点与存储经济学(L1/L2/L3)

- **缓存价值公式**:重算成本×复用次数−存储成本;廉算贵存(gain 级不配缓存)。用户手动 freeze 永有最终决定权。物化点家族成员名=存储政策:cached(raw 分身)/resident(压缩分身)/disk_cache(键=树哈希⊕制式)/lru;完整物化点=L1+L2+产线兜底(tiered),cached/resident=退化端点。
- **内存三档=格式即任务**(默认全驻内存;压缩既是省法也是任务适配):
  - **L1=raw 写回队列**(计算档):躺的是"未入库的唯一副本"(可再生缓存才可驱逐,唯一副本驱逐=丢工作)。生灭法:**算必落**(计算产出即入队)、**L2 有即死**(入库即注销)、**无上限**(队列长度是调度问题,失衡极端归落盘保底)。判据"只抓贵的":计算产出必落,解码命中不落;计算即触发(计算≡无 L2,顺手入队免检测)。伺候重复消费(计算链零解码)。
  - **L2=intra 单压**(预览档):无损压缩驻留,随机访问自由,伺候单次消费(预览足用)。**L2=独立结构体{容器+存入器}**(多源:协议/闲时/预判窗);存入器签名 (t)→void 自给自足(经流协议取帧,压完即扔)。
  - **L3=inter 时压**(分发档,外挂,协议外):~50-100×;GOP 内 I 帧=L2 等价物(一份数据顺序/随机双消费)。**不进流协议直通**(解码麻烦+天生有损;流协议只认 L1/L2,缺了重算)。smart rendering:L3 与导出同编码同参数时,重导出=未改动段流拷贝+失效段重编码,分钟级→秒级;L3 不止是缓存,是导出的预制品。
  - 键=树哈希⊕制式⊕格式档。
- **引用纪律**:持有引用期间被引用物不许死;**先压完再发通知**;完工消息只带身份(帧号 i64 值语义免费)不带本体;死期=完工通知带 t 按号索引删(并发下位置启发会杀错帧)。崩了没发完工消息的帧赖在 L1=正确语义(压缩未完成),走失败政策,不静默删。
- **入度判据(同居/分家)**:入度 1=同居(L1 同居流协议,唯一写入者=协议);入度 N=独立解耦+内存命令可达(L2 多源)。结构体可接受命令(泵分派到方法)。
- **L1=协议的唯一 raw 货架(2026-10-09 物理定稿)**:raw 永不"流进"函数——一切消费=借地址(零拷贝,L1 出借,调用方借用)。三路径合一:L1 有→直借;L2 有→解码落席再借;皆无→**产帧落生产者自己那条流的 L1**(每条流的 L1 只放自己的产品),下游跨流借地址读。**死亡统一律:死期 = L2 有 ∧ 无引用**——计算帧受"L2 无"保护至完工消息到达;解码帧出生即"L2 有",只靠引用保护,用完即死。旧法"解码命中不落"由此精化:不落的是**写回保护**,落的是**缓冲席位**。借用机制=席位 refcount(跨线程原子化)。**命令/查询分途**:"让对方行动"(存 t/预产窗)走消息队列;"问对方状态"(L2 有无/借压缩帧地址)同进程内走**加锁直读**——否则同步拉取被迫变成两消息一等待的 rendezvous,拉接口就异步化了。消息载荷=行动请求+身份(id/帧号)+地址+有无标志(纸条级,≤16B);地址可安全传递的前提=引用纪律(借了不死)。
- **半岛法(2026-10-09):合并判据按关系不按字段**。L2 与流协议的连接=半岛:读侧入度 1(协议独占查询)→加锁直读;写侧入度 N(协议/闲时/预判窗)→命令队列。"L2 并入流协议结构体"不成立,三笔账:①**队列的真正成因是线程边界**(存入器活在另一个泵上),不是结构体边界——合并结构体不能合并线程,完工消息跨线程照样要消息或标志位,一样都省不掉;②合并=协议从 24 字节同步拉取句柄重量级化为带队列带泵的 actor;③存入器要**跨流池化**(压缩工人池+全局优先级三轨:前台点播>预判窗>闲时),并入每条流=私养工人,全局排序消失。若写入侧将来真的只剩协议一源,入度判据会自己把 L2 化归为同居件——**形状跟关系走,关系变形状才变**。
- **帧地址交付三通道与延迟四法(2026-10-10)**:raw 地址的交付**永远直调,从不进广播命令队列**——同线程=函数返回值(主路径);跨线程=一次性信箱(future/条件变量,rendezvous,不是队列);命令队列只运"令"(身份+意图),不运待消费地址(消费者自给自足调 get)。"不能及时给地址"四法,按消费者物种选:①**等**(保底轨,机界——阻塞即其形态,等得起零博弈);②**报缺**(report 轨——立即返死状态 0×0,给可容忍"未就绪"的消费者);③**门禁**(has(t),人界播放——deadline 路径永不阻塞,没有就不播,欠账三选:等/跳帧/降级);④**发令+回执**(异步轨——把"取帧"拆成 fill 令+完工回执两步;**同步接口遇到不可预判延迟,答案永远是换时间轴=异步化,不是硬扛**)。
- **接口形态法(2026-10-10):查询与获取分离,通知消灭轮询**。has(t)=规划查询(advisory,供 deadline 决策:播/跳/降级);get(t)=原子获取(锁内查账+借用,政策档:produce 必给/report 死状态)。单动词重试型("给我帧"→没有→再刷新,503 心智)合法但**只配低频/人操作场景**(AI 客户端偶尔拉一帧);高频等待一律**完工回执(推),不轮询(拉)**——HTTP 的 Retry-After 是"提示你何时再来",完工回执是"到点我叫你",推比拉省。TOCTOU 防护:has 只供规划不担保,获取的原子性在 get 内部(引用纪律:借了不死)。
- **行业接口形态普查(2026-10-10,三个官方源已核实)**:五形态共存,无第六种——①**阻塞直给**(POSIX read/std::future::get)=保底轨;②**状态立即返回**(FFmpeg avcodec_receive_frame 的 EAGAIN="output is not available in this state",同步收发循环[官方文档已核实];Android dequeueOutputBuffer(-1))=report 档死状态;③**就绪查询+获取分离**(epoll 先问谁就绪再读/vkGetFenceStatus 查询+vkWaitForFences 等待/future::wait_for(0)+get)=has+get 门禁;④**双队列:发令队列+回执队列**(io_uring SQ/CQ:SQE 进、CQE 出、user_data 关联提交与完成,完成可阻塞 io_uring_enter 也可轮询 CQ[man7 已核实];IOCP;GPU submit+fence;HTTP 202)=fill 令+完工回执;⑤**句柄+异步完成通知**(WebGPU onSubmittedWorkDone/mapAsync 返 Promise,非阻塞回调[W3C 规范已核实];JS Promise.then)。超时=颗粒度中间档(dequeueOutputBuffer(timeout);Disruptor WaitStrategy 族:阻塞/让行/自旋/超时)。**接口形态经验:优先使用通知/回执/句柄,轮询只作有界兜底**;我们的延迟四法=这张地图换我们的词。**剪辑软件适配排序(2026-10-10)**:剪辑的访问模式=可预测的顺序流(播放 1× 前进+偶尔跳),故——**④(io_uring 型)为人界主力**:可预测→批量提前发令→产帧延迟从交互路径整体挪走;行业实证:AE RAM 预览=④+③(绿条=has(t)可视化)、Resolve decode-ahead 环形缓冲=④、剪映流畅=④+低清档兜底;**①阻塞拉取为机界骨**(Nuke 拉式求值,计算链内天经地义);**③为门**(has(t) 廉价规划);**②为兜底**(scrub 单帧/AI 低频);⑤为将来客户端/AI 的句柄形态。**我们把④作为低延迟播放的候选机制,须以自有基准验证;不把对其他闭源产品内部机制的归因当事实**。我们独立长出 io_uring 同构:SQE/CQE/user_data ↔ fill 令/完工回执/帧号。
- **⑤与④的真关系(2026-10-10):WebGPU 主体=④,⑤只是配件**。queue.submit=发令队列(SQ),GPU 在 queue timeline 异步消费——这就是④;mapAsync/onSubmittedWorkDone 的 Promise 只用于**稀有的 CPU 回读与同步点**(我们 gpu_demo 的 256 数回读正是⑤的正确用法:一次性回读,不是逐帧)。**逐帧 Promise 之弊**(为何⑤不适配核心渲染):①句柄按请求分配——30fps×N 流=每秒数千句柄的分配与簿记,而 io_uring 的 CQE 是环上槽位零分配;②通知粒度≠排干粒度——播放器按 deadline 周期排干账本(has),不等逐帧句柄;③无背压——Promise 可瞬发一万个,我们的产压闸在环上(SQ 满即缓);④热路径是确定性排干循环,不是 continuation 链。**通法:⑤=稀疏外部客户端的人体工学外套(AI/agent 拉帧/导出作业完成/一次性回读),④=内部管线的工业形态;⑤ 是 ④ 穿了件外套,不是竞争者。**
- **④⑤思想逻辑(2026-10-10)**:母题=同步调用把线程抵押在等待里,④⑤是两种解法但下刀位置不同。**④=把函数调用拆成两条账**:f(x)=y 变成 SQ 记 (x,ticket)(参数的异步化)+ CQ 记 (ticket,y)(返回值的异步化);两个环=两个独立节拍的缓冲(发令节奏归你/完成节奏归生产者),背压各自显形(SQ 满你慢发/CQ 满产慢完);环=槽位复用零分配;user_data=配对面不改的关联字段(完成无序,token 原样带回);本质=**调用的事件溯源化**——请求与完成都是只追加的不可变事件流,"在途集合"是两流的推导。**⑤=未来值对象化**:把"将来才存在的值"变成现在就能传递的一等值(替身),换到的是**组合性**(then/all/race)与**顺序心智**(把异步写回"看起来同步"的代码,async/await 是其语法完成态);内核=pending/fulfilled/rejected 三态机,单次不可逆迁移,结算后退化为纯值(可缓存可重复 then);回调=控制反转(被动被调),Promise=主动句柄(值可自由操作)。**分工:④管管道怎么流动(吞吐/背压/零分配),⑤管调用方怎么写代码(组合/可读/错误传播);④ 改结构,⑤ 改语法;对外的⑤ 里裹的永远是对内的④。**
- **环的赌注(2026-10-10)**:环的容量 N 吸收的是**波动不是趋势**——产压长期失衡(生产速率>消费速率)时,任何有限缓冲都只改变撞墙的时间,不改变撞墙本身(Little 定律:队列长=到达率×滞留时间,到达率>服务率→∞)。环的真正价值=**让债务有上限且显形**:满=信号,逼出政策(背压缓产/丢弃/降级/落盘);对比无界队列=赌"内存无限",债默默涨到 OOM——环把慢性死亡变成当场显形。命令环容量=允许的欠账上限,满=触发欠账政策,与欠账形态律同构:**债可欠,但必须欠得有限、欠得可见、欠得有政策**。
- **落盘=压力保底,与调配无关**:精心策略全部失效后的保命措施,不是策略的一环;降级顺序 **L3→L2→L1**(按编辑价值升序);溢出动作=格式不变纯搬运(廉价),转码只在闲时。OS swap=世界的保底(给不管理内存的人),我们抢在它触发前用自己的法律处理完(内存预算压 60-70%,热路径永不依赖 swap)。
- **驱逐加权分**(总内存超额时帧粒度挤兑):最近使用度÷(重算成本×fan-in);编辑态保底层(fan-in 高者)、预览态保顶层;策略按钮三档(编辑优先/预览优先/智能检测),政策插件,帧粒度非整流。
- **派生 DAG 存储律(持久化律)**:万物构成派生 DAG;必须存的只有源节点(树/参数谱/素材),其余一切(参数流/提取品/缩略图/渲染缓存/导出 mp4)都是**可选缓存**,存否=重算成本×使用频率 vs 体积。派生物落盘的唯一合法身份=可再生缓存,永不当真源;有更强真源的依赖已记载,自己就不必缓存。
- **缓存透明律(2026-10-10,用户)**:**.cut 与缓存的关系=代码与 CPU L123 的关系**——缓存对声明 100% 透明,是优化策略不是语义:cut 从不提及缓存,缓存永不出现在声明里;缓存键=树哈希⊕制式(内容寻址),缓存是声明的纯函数;删光缓存工程无损,缓存写错自动失效。语义住声明,优化住缓存,两层永不越界。
- **固化(bake)=预产+登记进素材表+树节点改引用**(派生→声明的行政区变更)。同一串字节可扮三身份(磁盘缓存/固化产物/素材),区别不在字节在**身份登记**;物与身份分离,身份是行政记录。谱系:点播缓存(全自动随树)→预产(自动策略随树)→冻结(手动脱离树成素材)→导出(分发离境),渲染机制共享,产物身份不同。
