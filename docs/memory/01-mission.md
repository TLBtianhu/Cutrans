## 使命宣言:剪辑软件界的 GNU(2026-10-09,用户口述种子)

**批判**:当代剪辑/数媒生态=强绑定+闭源。Adobe=订阅制+专有工程格式(.aep/.prproj)+插件绑宿主;剪映=免费(gratis)但闭源+云绑定+蠢人化。工程文件是专有二进制,用户的作品是厂商的人质。
**类比**:GNU 之前的时代——软件从自由共享(60-70 年代黑客文化,源码随机器走)转为私有化(1976 微软《致爱好者公开信》/AT&T 收紧 Unix 许可证);今天的创作工具走了同一条路。两个时代同构:工具厂商控制创作的生产资料。
**理想**:在剪辑及一切数媒领域复刻 GNU playbook——宣言先行(GNU Manifesto 1983;本宪法文档即是)/自由格式(.cut 可读文本=源码中心主义)/一切皆插件(≈Unix 一切皆文件)/逐件可用策略(gcc 模式:单件好用就有人用,不等整个系统)/搭时代变革期便车(当年微型机民主化硬件+Usenet 协作网,今天 AI 民主化能力+GitHub 分发)。
**反面教材(立法带上)**:①Hurd 陷阱——重新设计的整体永远难产,能赢的是今天就能替换一个零件的东西;②桌面问题——GNU/Linux 赢了服务器/手机/超算,唯独没赢桌面:用户是创作者而非工程师时,UX 是生死不是装饰(GIMP 停滞 vs Blender 吃掉 3D 界=对照组,光自由不够,要有持续全职工程+真实 UX;易用性是真需求,蠢人化是过度代偿,界限待立法);③剪辑界迄今抢到份额的"免费"是 Resolve/剪映(gratis 但闭源),开源剪辑器从没赢过——自由是信任结构不是卖点,产品力才是;回答"凭什么不重蹈 Kdenlive"的那部分=本宪法的协议细腰+AI 可读+插件化。
**关键差异**:GNU 有 POSIX 可抄(公开接口规范摆在那,照做就是替换件);剪辑界没有 POSIX——Cutrans 须同时写规范和实现,更难,但谁写出好规范谁就定义领域。先例:VST=音频界事实标准(创作软件接口确实可跨宿主),CLAP=音频界的开源回答。
**许可证定案(2026-10-09):MIT**。采纳性优先(技术价值=技术×可采纳性,MIT 最大化可采纳性);不玩 copyleft 强制——与"代码里镶版权本无防线、防线在外部法律"的认知一致:既然防线在外不在内,就在许可证上把自由给足。

**使命升级(2026-10-09):用户即开发者**。创作者早已在用架构思维——图层=作用域、合成嵌套=函数调用、轨道发送=依赖注入、素材文件夹=项目架构;缺的不是认知能力,是**同构的桥**:软件从未把这些操作命名成它们本来是的编程概念。"桌面问题"的归因修正:GNU/Linux 没赢桌面,不是创作者脑子不够,是桥没建+技能资本被厂商劫持(见下)。Cutrans 的桥=宪法兑现为体验:**vibeediting 与 vibecoding 是同一件事**(内置 agent loop 的第一句话)。远期形态:agent 发现重复需求或尚无的效果 → **现场编译一个新 .cop 装上**——工作与开发无界限;此愿景的承重件=失败分层+装配器门卫(agent 写的器必须落在可捕获红标区,永不可崩宿主)。
**技能资本的产权**:创作者的知识不应沉淀在闭源软件的 UI 肌肉记忆里(厂商一倒/盗版一清,资本归零——"知道在哪按什么按钮"≠剪辑技术本身);工作流必须落在用户自己拥有的可读声明(.cut)里:可携带、可版本化、可跨软件。
**AI 抵触的解药=透明**:创作圈恨的不是技术,是"不劳而获"的黑盒(术力口/MAD 圈崇尚个人勤奋,熬夜做同人是荣誉);.cut 让 AI 的每一步可复读/可改/可撤销——可审计性是对"AI 作弊感"的设计回答,不是更强 AI。
**编程亲和度梯度(设计法)**:创作圈对编程的抗拒=纯画 > 动画 > 音乐,与媒介本身已暴露的形式结构多少成反比(混音台=信号流图、动画=时间轴、纯画=最少显式结构)——他们反的不是结构,是"长得像数学课的记号"。设计含义:各模态编辑器暴露结构的速率,应匹配该工艺已有的结构显性度。
**社会学补记**:东方专业分类压制通才思维;但君子六艺(礼乐射御书数)乐与数本就同桌——"编程看不起艺术"是现代病,不是传统。

**开发者-用户鸿沟的实证裁决(2026-10-09 调查)**:
- **学术层:能力不是变量,鸿沟是认知框架问题——可弥合,不可消灭**。知识诅咒(Newton 敲节奏实验,Stanford 1991:敲节奏者预测听众猜中率 50%,实际 2.5%——懂了就无法想象不懂);专家盲点(教育心理学:专家的组织化知识使其看不见新手的困难);虚假共识效应(NN/g,已核实:设计师/开发者/甚至 UX 研究员都把自己的行为投射到用户身上,解法=真实用户测试)。Cooper 的互补论点:程序员的认知风格确实经训练而不同("Homo logicus"),所以让程序员直接设计交互必败——但他的解法是交互设计学科化+persona 方法,**不是人人通才**。
- **行业层:创作工具的起源期几乎都是从业者自造**(Steinberg 创始人是键盘手、Image-Line 的 gol 程序员+音乐玩家、Blender 诞生于动画工作室内部生产、Resolve 前身是调色台公司;训练集,中-高置信);**制度化 dogfooding 最强案例=Blender Studio open movies**(官网已核实:开发者每年用最新版 Blender 亲自拍片,三目的=维护开源制作管线/持续测试推动开发/开放分享制作知识);大厂阶段=开发者-用户同一性制度性稀释,代理机制补位(pre-release 计划/聘专业用户做 PM/UX 研究岗位)。dogfooding 只在员工=代表性用户时有效(微软 Office 有效;Google+ 反例:员工爱用、外部失败)。
- **框架层**:trading zones(Galison)+boundary objects(Star & Griesemer)——鸿沟的治理=建边界对象与交易区,不需要人人通才。persona/可用性报告是**有损**边界对象;**.cut 是宪法内建的无损边界对象**(开发者读 AST/创作者读菜谱/AI 读程序,三方各用自己的词汇读同一份声明);"用户即开发者"使命=把交易区直接铺进产品内部(agent 现场造器)。
- 调研环境注记:GFW 墙 Wikipedia/镜像站、Bing/搜狗反爬;已核实项=Blender 官网+NN/g 官网,其余训练集并标注置信度。
