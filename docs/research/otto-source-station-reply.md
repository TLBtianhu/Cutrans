## 一、总体回应

**模型同意，骨架不动。**

Source / Station / Projection / Snapshot 这套四分法，OTTO 当前主线**已经大体符合**，
不需要为此把应用改成另一套 VM，也不需要引入 Cutrans 的 Station 概念。
真正需要修的是**快照与工作视图之间的接缝**，不是对象模型。

OTTO 继续负责：**Source 索引、快速预览、宿主移交**。
Cutrans 的内存 Station 保持独立，双方通过**显式 load / export** 协作，不共享活动对象。

## 二、分层判断（逐项对应到代码）

| OTTO 的对象 | 归属 | 依据 |
| --- | --- | --- |
| `store.Library` | **Source 的一次性快照**（只读真源） | `zig/core/src/index.zig` 头：加载一次、一个字节都不改 |
| 滚动 `Index` | **Station 的工作视图**，不是共享真源 | 事件流上按到达顺序应用 `Change` |
| 只读 Browse | **Projection**：真实目录的分页观察 | `zig/app/src/browse.zig`：懒枚举、分页、具名拒绝、零写入 |
| 预览 Provider | **Projection**，且带覆盖范围 | 首帧 / 缩略图 / 波形前缀 |
| `otto-thumb-host.exe` | **故障隔离进程**，不是宿主启动 | 拖出到 FL Studio / Melodyne 才是移交 |
| 渐进波形 | **部分 Projection** | 总长未知回退整段；头部说谎则从完整 PCM 重算 |

## 三、风险排序（按"会不会让用户丢东西"）

### ① 最高：`Index` 与 `Library` 的读取语义不一致 —— 已核实

```
query.* 仍读 Library 快照
created 样本 folder_id = null，且不会进入 SampleFolder.sample_ids
```

**后果**：写入更新了视图，查询却读上一个年代的快照。用户看到的是"我加进去了，搜索/分组里没有"。

**最小修法**：二选一——实时查询统一走 `Index`；或明确声明 `Index` 只是临时收集器，
重建前不承诺完整业务视图。**不允许两种口径并存。**

### ② 高：`mtime` 不落盘导致无身份卷上的注释失联 —— 已核实

```
store.load 不解析 mtime（字段保持 0）
FallbackKey = path + size + mtime
```

**后果**：FAT32 / exFAT / 网络盘没有 File ID，身份只能靠 `path+size+mtime`；
重启后 mtime 归 0，**注释按错误身份重连或连不上**。

**最小修法**：已知 `mtime` 随快照落盘并在 load 恢复；
无身份卷上给出"最近可信身份 + 迁移策略"，**不许默默丢注释**。

### ③ 中：`Sample.id` 与 `StableKey` 的重连

`Sample.id` 是业务对象 ID（`model.zig:133`），注释用 `StableKey`（`model.zig:75`）。
要验的是 rename → 重扫 → 重启 → 跨库导入之后，**分组与目录关系是否完整**。
重点防"注释保住了，分组却丢了"这种半残状态。

**最小修法**：一组针对性测试，不是重构。

### ④ 中：PCM 与解码缓冲未纳入驻留预算

渐进预览**最终持有完整 PCM 并移交所有权**。
10 分钟 48 kHz 立体声约 **110 MiB**，比当前整个应用的内存预算还大。

**最小修法**：三档——只留波形 / 有界播放窗 / 全解码，并把 PCM 计入预算。

### ⑤ 低：Coverage 统一表达

`truncated` / `has_more` / `pending_metadata` / `waveform_version` 都是好机制，只是分散。
可以收敛成统一的"覆盖范围"表达，**不必为此改动行为**。

## 四、两处需要澄清（不是反对，是边界要说准）

### 1. OTTO 有持久层，但那是 **Source 的快照**，不是 Station 的持久化

文中"Station 不设计持久层"这条，对 Cutrans 的内存工作区成立；
但 OTTO 的 `library.otto` **本来就要落盘**——它是"用户显式登记的 Source 快照"，
不是"把内存 Station 存下来"。

所以 OTTO 的持久化路径是：

```
用户导入（显式动作）→ 生成/更新 Source 快照（落盘）
启动时 load（显式动作）→ 得到只读快照 + 工作视图
```

这与"加载意图不等于恢复承诺"是一致的：**我们恢复的是 Source 快照，不是内存现场。**

### 2. 目录监听不是"后台替换活动对象"

文中建议"只在事务边界检查变化，不在后台替换活动对象"。
OTTO 的 Browse 用 `ReadDirectoryChangesW` 监听目录，**更新的是只读投影**：
目录内容变了 → 重扫并合并到分页视图，选中项按文件身份跟踪。

**这不是把 Station 里的活动对象换掉**——浏览模式里没有可编辑的活动对象，只有投影。
如果未来 OTTO 出现"正在编辑的对象"，那时才需要"显式 sync / 冲突策略"那一套。

## 五、与在途改动的关系（重要）

当前有一条分支 `feat/library-folders` 正在做**库模式文件夹层级 + 库格式 v1→v2 迁移**。
本文的前三条**恰好落在它的改动面上**，所以处理方式不是另开一摊，而是**交付后按清单验收**：

```
① mtime 是否随快照落盘并在 load 恢复（趁格式升版一起做）
② created 样本的 folder_id / 分组关系是否增量维护
③ 查询是否仍读旧快照（必须一并解决，否则新格式延续老毛病）
```

随后单独补：**rename → 重扫 → 重启 → 跨库导入的分组/注释重连测试**，
以及 **PCM 与解码缓冲纳入驻留预算**。

## 七、对"Cutrans 应如何接入"的回应

同意你给出的最小面，并补充两条 OTTO 侧的保证：

- `asset.preview` 会带**覆盖范围**（前缀/分页/是否完整），不把部分内容冒充完整素材；
- `host.launch` 与 `preview` **不会共用动词或返回类型**——拖出移交与预览在 OTTO 里就是两件事。

`zig-audio` 是解码 Provider，不是素材真源；nanoui 是可选 UI 投影。
外部文件进入 Cutrans 仍须走你们的 VNE 授权，**OTTO 不会提供绕过它的旁路**。

## 八、联合验收矩阵（在你第六节基础上补三条）

你给的十条我们接受，另外补三条来自本轮实测的坑：

- **峰值而非当前值**：加载 20 万行时峰值可越过预算再回落，**必须按峰值判**；
  OTTO 已改为 `max(working_set, peak_working_set)`，并在装不下时具名拒绝剩余行。
- **基线 CPU**：发给用户的二进制若按构建机 native 编译，会在没有 AVX512 的 CPU 上
  **非法指令、进程静默退出**。OTTO 已把默认目标钉在 `x86_64_v2`。
  这条对 Cutrans 的 Zig 构建同样适用，建议一并钉住。
- **部分投影的最终一致性**：渐进波形在头部声明与实际帧数不符时**必须重算**，
  否则"按错误总长切桶"会以完整波形的样子出现。

## 九、我们不做什么

- 不把 OTTO 改成通用编辑器或另一套 VM；
- 不为 Station 设计持久层（OTTO 的落盘是 Source 快照）；
- 不用"前缀共享""缩短身份"等方式换内存（`Sample.file_path` 必须始终指向完整绝对路径）；
- 不做后台隐式同步或实时镜像；
- 不让预览、宿主启动、拖出移交重新混为一谈。

## 补充：接受 Catalog / Content 两种快照的区分（2026-11-02 后续）

`docs/research/otto-source-station-followup.md` 补的这一条我们接受，并据此修正自己的措辞：

- **`library.otto` = Catalog Snapshot**：恢复索引、来源、注释、分组与格式版本；
  **不是原媒体的备份**，原文件丢失后不能保证内容可独立恢复。
- 只有**保存完整素材字节、或足以完整再生的声明与依赖**的导出物，才叫 Content Snapshot。
- `Library` 的"只读真源"含义也应限定为**这份快照自己的真源**，不是实时 Source 的真源；
  实时查询必须明确读取哪个版本。

落到 OTTO 的动作：
1. 文档与知识库不再把 `library.otto` 描述成"素材的备份"；
2. 若将来提供"导出为独立内容"的能力，**必须走 Content Snapshot 的定义**（含完整性、依赖与格式版本校验），
   不能拿目录快照冒充；
3. `feat/library-folders` 的验收顺序按 followup 执行：mtime 落盘恢复、查询与 Index 一致、
   created 样本的目录/分组增量维护。
