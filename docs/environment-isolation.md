# 运行环境、分发与本机验收边界

本页描述 2026-11-06～07 隔离修复后的代码契约。实际执行证据及未完成项见 [本轮实施记录](memory/2026-11-06-isolation.md)。旧记忆中的安装成功、升级通过和清理策略属于当时版本，不能替代本版验收。

## 三个独立维度

| 维度 | 当前取值 | 决定什么 |
| --- | --- | --- |
| 运行用途 `purpose` | normal、diagnostic、verification、replay | 是否允许默认数据根；实例标记必须匹配用途，诊断与验收不能接管正常会话 |
| 分发形态 `form` | development、portable、installed | 程序与资源布局、默认数据根；参数不能推翻产物声明 |
| 发布频道 `channel` | development、preview、stable | 实例标记与产物身份；当前仅一个安装 AppId，频道不构成可并行注册的多个产品 |

“被打包”不会自动授予系统登记能力。便携包不登记系统，安装器才处理当前用户卸载项、开始菜单入口及 `.cut` 关联。开发频道的安装包仍有同一 AppId，不能拿它在现有体验用户中做隔离安装试验。

## 数据归属

| 位置 | 归属与用途 | 删除规则 |
| --- | --- | --- |
| 仓库源码、`assets/`、`config/`、`third_party/` | 开发材料和只读输入 | 不当作运行数据目录 |
| `.zig-cache/`、`zig-out/` 或显式 build prefix | 可重建构建缓存、程序、清单、安装器 staging | 可重建；新运行不得在 staging 默认生成日常数据；历史验证记录先保留辨认 |
| 工作区 `.cutrans-dev/` | development normal 的文档、History、任务、授权、缓存与 Session | 不进分发包，不随清理构建输出删除 |
| `scratch/verification/<case>-<uuid>/` | 新建且有所有权标记的独立验证案例、合成数据、日志和验收证据 | 默认保留；删除权限来自精确根和标记，不来自 `CUTRANS_BUILD_PREFIX` |
| 用户选择的便携根 `data/` | portable normal 的运行数据 | 复制、替换程序时保留；不能把整个便携根当可丢弃程序缓存 |
| 安装根 `data/` | installed normal 的运行数据 | 安装、同资产重装和默认卸载保留 |
| 实例数据根下 `library/versions/<id>/<sha256>.bin` | 文档／History／Job采用的库Source版本字节 | 持久用户数据，不属于缓存或构建输出；默认保留，禁用自动回收；写入失败不发布采用结果 |
| 用户工作区、外部 `.cut`、素材和导出目标 | 用户作品；与程序根、运行数据根是不同概念 | 打开外部文档只读授权，保存会话副本；不得通过诊断覆盖原件 |
| 旧路径和归属不明的非空目录 | 尚待核实的历史数据、残留或证据 | 不按名称、时间或是否已卸载决定删除，不自动迁移合并 |

Pack 的 `pack://` 是只读输入；Session、持久资源库、可重建缓存和临时数据依旧分层。当前未实现账号凭据管理、更新缓存服务或遥测服务，不能因目录为空就臆造它们的迁移策略。

## 唯一启动上下文

`vne/product.zig` 持有产品 ID、版本、AppId、ProgID、扩展名与默认服务策略。构建生成 `cutrans-context.json` 和安装器 include；`.zon` 的包版本必须与产品版本一致。Portable 与 installed 的 context 不同，其 VM 清单也分别哈希对应 context。

启动先解析本身的实际 EXE 位置、声明的 form/channel、物理规范路径及实例用途，再校验资源和加载 Runtime/Shell。缺失、错误或不兼容声明直接失败；不从 cwd、项目 `.env`、HOME、USERPROFILE、APPDATA、LOCALAPPDATA 或其它产品的目录推测默认数据。绝对显式数据覆盖仍受 Pack 分离及实例身份检查约束。Windows 路径大小写、`..` 与目录联接的物理别名使用相同实例根。

`cutrans-instance.json` 记录 product/form/channel/purpose。验证用途必须给出独立绝对数据根，拒绝非空、无标记目录和身份冲突。无标记的旧正常会话仅在对应形态的默认数据位置且识别到 Cutrans 持久格式时可读取，不重写历史身份；其它位置保留待核实迁移，不允许诊断接管。`context`、`status` 和诊断 `--inspect` 不创建数据。

所有可写入口使用共同边界：程序根内仅专用 `data/` 树可承载状态，不能写进任一可选 Pack；development 整个构建根不可承载运行数据。对程序与目标数据两条祖先链检查构建声明，因此复制出去的便携入口也不能显式把数据指回构建输出。只读查询仍可报告 staging 的默认路径。

| 真实入口 | 上下文及行为 |
| --- | --- |
| `cutrans_vm.exe` | console `context/start/status/stop/restart/desktop/library/activate-runtime`；共享 bootstrap 解析 |
| `cutrans_bootstrap.exe` | headless、诊断与回放；共享同一解析，写入必须显式独立数据 |
| `cutrans_vm_host.exe` | 独立后台 Host；相同实例标记、规范路径、锁与 Runtime 校验 |
| `cutrans_shell.exe`、`cutrans_library_nanoui.exe` | 附着同一 Host；先校验 Shell，成功后才提交选择；启动子进程固定 cwd 为程序目录 |
| `cutrans_desktop.dll`、Runtime DLL | 经显式绝对 Pack 路径和 ABI 配置进入；DLL 搜索只允许所选目录及 System32 |
| `cutrans_diag.exe` | `--inspect` 只读；写入探针强制 `--verify-data-dir`，验证 Pack 后才建独立实例，不写 Pack 或外部原件 |
| Web、更新器、账号与遥测 | 当前没有单独产品 Web/更新/账号/遥测入口；NanoUI 关闭 WebView2 和隐式 KV。context 启用未配置服务会被拒绝 |
| 安装器、生成卸载器 | 产品声明生成身份；先核验所有权、真实路径、进程状态并备份要改的登记和快捷方式 |

ImGui 的默认 `imgui.ini` 持久化已关闭。第三方源码中的演示应用、服务能力或默认设置不等于本产品公开入口。

直接 C ABI 的 `Config` 是受信任调用方传入的资源／数据契约，底层检查物理路径分离；它没有自行推断发布频道或用途的能力。这里的完整身份检查覆盖公开 EXE 与其启动链，不能据此宣称任意外部 ABI 客户端或不可信插件已受隔离沙箱保护。

## 安装、重试与失败

安装前后诊断各用安装器专属临时数据，不允许把 `VerifyDataDir` 指到真实会话。安装前完整校验提取出的实际资产；失败停止在复制和登记之前。已有安装必须同根且归当前登记所有，先正常保存并停止 Host，再确认相关进程退出。找不到控制入口不会假装已经停止。

当前只接受完全相同程序资产的幂等重装。变更资产升级没有已验收的文件／登记／Runtime 选择整体回滚事务，故在复制前拒绝；不能称为已支持无损升级。显式 Runtime 激活先校验候选、创建和握手成功后再提交选择，失败保留原锁，允许修复后重试。该动作可能按现有恢复语义标记中断任务，不是任意用户数据上的只读操作。

安装后失败返回 9 并留下阶段状态；不会把 Inno 的 post-install 回调误称为自动回滚。卸载器必须仍拥有登记和当前根，保存／停止或备份失败则中止，保留程序、登记和数据。旧卸载器不能拿来清理其它安装。当前用户实机上尚未执行这版安装、失败卸载或重试，相关代码契约须由独立 OS 用户／VM 补验。

## 本机清理与发布

已有机器内容先只读盘点：清单和文件哈希、活动进程、卸载项、快捷方式目标与参数、关联、PATH、任务和服务。当前清理白名单为空；真实会话、作品、凭据、历史安装证据和归属不明目录均保留。没有实际登记／快捷方式修改，所以没有把只读快照冒充恢复备份。

测试清理必须验证精确路径及所有父级无 reparse，拒绝任何内部链接，删除不跟随链接。仅本轮创建的合成夹具可删除或替换；真实数据不在授权名单内。

源码测试、便携产物测试、安装器提取预检、完整安装升级卸载是四种不同证据。`--artifact-check` 的 `/PreflightOnly=1` 返回 7，表示已验证且故意停止安装，不是安装成功。注册测试要求独立 OS SID 证明，单改 HOME 不合格；不冒用系统管理的测试账号。

当前尚未发布新的运行分发版本；源码主线推送不等同于应用发布。将来发布必须选定已经完成相应验收的同一份产物，并核对记录的 SHA-256；重新构建得到的新文件必须重新验收，不能沿用旧记录。
